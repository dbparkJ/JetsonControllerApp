# GEO-X 위성항법시스템(GNSS) 정확도 실외 시험 계획서

- 문서 상태: 시험 전 계획(2026-10-26 작성). 결과는 7장 기록 양식에 적는다.
- 범위: 실외 시험 계획. Claude는 장치를 읽기만 하고, 수집·설정 변경·케이블 조작 같은 장치 변경은 단계마다 사용자 승인 뒤 한다.
- 시험 기준일: 2026-10-26

## 0. 한눈에 보기

목적은 GEO-X의 위성항법시스템(GNSS; Global Navigation Satellite System) 위치가 실외에서 낮은 정확도를 보이는 원인을 구분하는 것이다.
현재 보정과 안테나 조건을 기록한 뒤, 개활지·보정 스트림·카메라 USB3·장소·이동 조건을 차례로 비교한다.

약어와 판정 용어:

- 실시간 이동 측위(RTK; Real-Time Kinematic): 기준국 보정으로 정밀도를 높이는 측위 방식.
- RTK fixed: 정수 모호정수가 고정된 센티미터급 해. RTK float: 모호정수가 아직 고정되지 않은 해.
- 차등 GPS(DGPS; Differential GPS): 코드 기반 보정 해. RTK fixed와 같은 뜻이 아니다.
- 수평 위성 배치 지표(HDOP; Horizontal Dilution of Precision): 위성 배치의 기하 품질. 실제 오차를 직접 재는 값은 아니다.
- 첫 위치까지 시간(TTFF; Time To First Fix): 수신기 시작 또는 재시작부터 첫 유효 항법 위치까지의 시간이다. 보정 재개 뒤 RTK 해를 얻는 시간은 RTK 수렴 시간으로 따로 기록한다.
- RTCM(Radio Technical Commission for Maritime Services): GNSS 보정 메시지 표준. NTRIP(Networked Transport of RTCM via Internet Protocol)은 이를 인터넷으로 전달하는 방식이다.
- 다중 신호 메시지(MSM; Multiple Signal Messages): 여러 위성군·신호 관측을 전달하는 RTCM 계열.
- 반송파 대 잡음 밀도(C/N0; carrier-to-noise density ratio): 신호 세기 지표. 현재 구성에서는 직접 볼 수 없다.
- 원형확률오차(CEP; Circular Error Probable): 중심 위치에서 표본 거리의 중앙값. 2DRMS(twice distance root mean square; 수평 거리 제곱평균제곱근의 2배)는 동·북 방향 분산으로 계산하는 산포 지표다.
- VRS(Virtual Reference Station)는 가상 기준국이다.
- GPS(Global Positioning System)는 미국 위성항법시스템이다. NMEA(National Marine Electronics Association) GGA는 위치·fix 문장, RMC(Recommended Minimum Navigation Information)는 최소 항법 정보 문장이다.
- A/B/A/B는 조건 A와 비교 조건 B를 번갈아 반복하는 순서다.
- SBAS(Satellite-Based Augmentation System)는 위성 기반 보강 시스템이다. 국내 KASS(Korea Augmentation Satellite System) 등 보강 신호가 GGA의 DGPS 표시에 영향을 줄 수 있다.

### 지금까지 본 근거

- 분석된 13개 수집 모두 GGA `fix_quality=4`(RTK fixed)가 0회였다.

### 가장 유력한 원인 후보

1. **높음 — 보정 스트림과 수신기의 공통 신호·위성군 부족 또는 기준국 기선 문제.** 수신기는 L1/L5 판이며, 과거 GUMC·GANS RTCM31 광고는 GPS 1004(L1/L2) 관측과 MAC 메시지 중심이었다. 실제 지원·사용이 확인되는 경우 공통 주파수는 L1뿐이다. 약 14 km로 표기된 기선에서 L1만 공통이면 fixed가 어려울 수 있으나, 실제 payload·적용 여부는 확인되지 않았다.
2. **높음 — 카메라 USB3·공유 허브의 RF 또는 버스 영향.** GNSS와 카메라는 같은 VIA 허브의 USB2/USB3 면에 있다. 카메라 복구 때 float가 집중됐지만 통제된 OFF 시험은 아니었다.
3. **중간 — 안테나 대역·설치·접지판·하늘 시야, 건물·차량의 다중경로.** 설치 기록이 없고 10/23 HDOP가 높았다.

## 1. 현재 구성

### 수신기·안테나·USB

| 항목 | 확인된 사실 | 현장 기록 |
|---|---|---|
| 수신기 | 과거 MON-VER 기록: `ZED-F9P`, `HPGL1L5 1.40`, `PROTVER=27.40`. L1/L5 판 펌웨어로 보이며 현재 새 식별 조회는 하지 않았다. | 실제 모델·펌웨어는 과거 기록 기준임을 표시. 재조회는 **[승인 필요]** 전용 세션에서만. |
| 주파수 | u-blox 릴리스 노트 UBX-23010071(HPG L1L5 1.40) 기준 GPS L1/L5 등을 지원하며 기본 설정에서 GPS L5와 NavIC L5는 꺼져 있다. L2는 이 펌웨어에 없다. 현재 저장 설정과 실제 신호 사용은 미확인. | 현재 신호 활성 여부를 추정하지 않는다. |
| 안테나 | 모델, L1/L5 지원, 장착 위치·높이, 접지판, 케이블 길이와 USB3 케이블과의 거리 기록이 없다. | 모델 라벨, 사진, 방향, 높이, 케이블 경로, 접지판을 현장에서 확인. |
| USB | GNSS는 VIA 허브 USB2 쪽, 카메라는 같은 허브 USB3 쪽으로 연결된 기록이다. 카메라 링크는 5 Gbps, GNSS USB는 Full-speed 12 Mbps로 확인됐다. | 실제 연결이 바뀌었는지 `lsusb -t`로 읽기만 한다. |
| 직렬 수신 | `/dev/serial/by-id/usb-u-blox_AG_-_www.u-blox.com_u-blox_GNSS_receiver-if00`가 과거 `ttyACM0`를 가리켰다. 파이프라인 또는 센서 모니터가 소유한다. | 포트를 열지 않는다. 소유자만 조회한다. |

### 보정 경로와 설정

보정 스트림은 국토지리정보원 공개 캐스터 `gnssdata.or.kr`의 마운트포인트를 쓸 수 있다. NTRIP 사용자명·비밀번호·토큰은 문서나 공유 로그에 쓰지 않는다.

| 설정·경로 | 확인값 |
|---|---|
| 자동 마운트포인트 | `rtk_ntrip_auto_mountpoint: true` |
| 형식 필터 | `rtk_ntrip_mountpoint_format: RTCM31`. 공개 소스테이블의 RTCM31 109개 중에서 선택하는 설정이다. RTCM32는 144개로 별도다. |
| 위치 대기·연결 시간 초과 | `rtk_ntrip_position_wait_s: 10.0`, `rtk_ntrip_data_timeout_s: 15.0` |
| 후보·재선정 | 최대 12개, 300초마다 재선정, 1,000m 이상 가까워질 때 전환 후보, 위치 최대 나이 30초. |
| 장치 직접 경로 | 장치의 NTRIP client가 캐스터에 직접 접속하는 실행 경로. 9/16 기록에서 사용했다. |
| 폰 중계 경로 | 폰 중계(Wi-Fi Direct)를 통해 보정 payload를 전달하는 실행 경로. 10/23 기록에서 사용했다. 내부 주소·포트는 기록하지 않는다. |
| 마지막 실외 관찰 | 10/23에는 `GUMC-RTCM31` 연결 기록과 뒤이은 `PAJU-RTCM31` handover가 있었다. 현재 연결 경로·마운트포인트는 당일 읽어서 확인한다. |

실제 마운트포인트 선택은 위치와 실행 경로에 따라 달라진다. 화면의 중계 등록이나 NTRIP 연결만으로 보정 적용을 판정하지 않는다.

### 위치 품질 판정과 관찰 공백

| 원시 GGA / 센서 상태 | 앱의 위치 표시 | 시험 기록 분류 |
|---|---|---|
| `fix_quality=4`, `rtk_fixed` | 정밀 | fixed |
| `fix_quality=5`, `rtk_float` | 대략 | float |
| `fix_quality=2`, `dgps` | 대략 | DGPS |
| `fix_quality=1`, `gps` | 대략 | 단독 측위 |
| `fix_quality=0`, `none` | 위치 없음 | no fix |
| 자료 부재·오래됨·미인식 | 위치 미확인 또는 없음 | 관찰 공백으로 따로 기록 |

앱의 “대략” 라벨은 미터 오차를 예측하지 않는다. HDOP·위성 수·차분 나이로 위 분류를 덮어쓰지 않는다. 실시간 앱 상태는 대략 2초 관찰이므로 짧은 float를 놓칠 수 있다. 판정은 가능하면 10 Hz 원시 GGA로 한다.

### 볼 수 있는 값과 볼 수 없는 값

| 값 | 지금 볼 수 있는 경로 | 한계 |
|---|---|---|
| fix, 좌표·고도·위성·HDOP | 앱 GNSS 위치 상세, `status.json`, 실행 로그 일부, 수집 `gps.csv` | GGA 위성 수는 12에서 잘려 있다. HDOP는 정확도 자체가 아니다. |
| NTRIP 연결·RTCM byte 누적 | `status.json`의 `ntripConnected`, `rtcmBytes`; 로그의 `ntrip=`, `rtcm_bytes=` | byte 증가는 호스트가 RTCM frame을 전달한 증거다. 수신기 적용 여부는 증명하지 않는다. |
| 차분 나이 | `status.json`의 `differentialAgeS`, `gps.csv`의 `differential_age_s` | 기존 자료 모두 비어 있다. 비어 있음을 0초로 해석하지 않는다. |
| 기준국 ID | status의 `referenceStationId`, `gps.csv`의 `reference_station_id` | ID만으로 실제 기준국·거리·보정 방식을 식별하지 못한다. |
| C/N0, 신호별 사용 위성, 재밍·스펙트럼 | 현재 표준 NMEA/상태 화면에서는 확인 불가 | C/N0, UBX `NAV-SIG`, `RXM-RTCM`, `MON-RF`, `MON-SPAN` 등은 승인된 전용 계측이 필요하다. |
| 수신 신호 기록 | 배포되면 status 키 `rtcmSignals`, 실행 로그, 앱 진단 화면에서 받은 RTCM 메시지별 GPS L1C/L5, Galileo E1/E5a, BeiDou B1I/B2a 등 신호와 기준국 ID·거리·메시지 번호를 확인할 수 있다. | 수집 파이프라인 릴리스에 기능이 반영된 뒤에만 확인한다. |
| 절대 정확도 | 기준점 좌표와 동시 측정으로 계산 | 기준점·좌표계·안테나 위상중심이 맞지 않으면 계산 불가. |

개발자 참고: fix 분류·폰 중계 등록 `backend/jetson_control/mobile_rtk.py`; 관찰 공백·품질 요약 `backend/jetson_control/field_quality.py`; 정밀·대략 표시 `app/src/main/java/com/example/jetsoncontroller/ui/field/QualityPresentation.kt`; 폰 중계 `app/src/main/java/com/example/jetsoncontroller/data/rtk/MobileRtkRelayManager.kt`. 장치 NTRIP 클라이언트는 수집 파이프라인 저장소 `geonova-depthai-mapper` 릴리스의 `runtime.py`다.

## 2. 원인 후보와 가르는 법

1·2번은 둘 다 가능성이 높고 함께 작동할 수 있다.

| 순위·가능성 | 근거와 미확인 점 | 가르는 시나리오 |
|---|---|---|
| 1. 보정 스트림의 공통 신호·위성군 부족, 보정 방식 또는 기준국 기선 — **높음, 우선 가설** | 과거 수신기 기록은 L1/L5 판이다. 서울시 GUMC·GANS RTCM31 광고는 GPS 1004 관측(L1/L2)과 MAC 메시지 중심이며, 이 수신기와 공통인 주파수는 지원·사용이 확인되는 경우 L1뿐이다. 약 14 km로 표기된 기선에서 L1만 공통이면 fixed가 어려울 수 있다. 당시 실제 payload·메시지 지원·적용 신호와 정확한 기선은 미확인이다. 레거시 메시지(1001–1004·1009–1012) 지원 표기가 u-blox 문서끼리 엇갈린다. [인터페이스 문서 UBX-23006991 R02 §4.3](https://content.u-blox.com/sites/default/files/documents/u-blox-F9-HPG-L1L5-1.40_InterfaceDescription_UBX-23006991.pdf)는 입력으로 나열하지만 [Integration manual UBX-18010802 R16 §3.1.5.2](https://content.u-blox.com/sites/default/files/ZED-F9P_IntegrationManual_UBX-18010802.pdf)는 이 펌웨어에서 지원하지 않는다고 적는다. 10/23 float는 일부 사용의 간접 근거일 뿐이며, 실제 사용은 RXM-RTCM으로 확인한다 **[승인 필요]**. | S2에서 보정 없음·현재 스트림·가까운 다중 위성군 단일 기준국을 비교한다. 실제 메시지·신호 사용 확인은 **[승인 필요]** 전용 계측으로 한다. |

## 3. 목적과 합격 기준

제조사 RTK 지표는 수평 CEP 0.01 m + 1 ppm이다([ZED-F9P-15B 데이터시트 UBX-23009090](https://content.u-blox.com/sites/default/files/documents/ZED-F9P-15B_DataSheet_UBX-23009090.pdf)). 이 시험의 p95·2DRMS와 같은 숫자로 비교하지 않는다. 아래 숫자는 이 시험의 현장 프로젝트 목표이며 제조사의 보장 합격선이 아니다. 개활지, 10 km 안쪽 기선, 다중 위성군·다중 주파수 보정이라는 조건이 확인될 때 비교한다. 조건이 충족되지 않으면 목표 미달만으로 수신기 고장을 판정하지 않는다. CEP50, 기준점 오차 p95, 고정 해의 2DRMS는 서로 다른 지표이므로 같은 숫자로 직접 비교하지 않는다.

| 지표 | RTK 현장 목표 | 현재 기대치·해석 |
|---|---|---|
| 보정 전달 재개부터 첫 RTK fixed까지(RTK 수렴 시간) | 반복 시도가 있을 때 중앙 60초 이하, 최장 120초 이하 | 기존 기록의 fixed는 0%. 단일 시도는 그 시도의 시간만 보고하고, 600초까지 미고정이면 관찰 종료 시 미고정으로 기록한다. |
| fixed 비율 | 첫 fixed 뒤 정지 10분 중 95% 이상 | 10/23 기준 0%. DGPS·단독 측위가 대부분이었다. |
| 기준점 대비 수평 오차 | 95백분위 3 cm 이하 | 기존 자료에 참값이 없어 현재 오차는 미확인. 기존 기록의 0.5~3 m는 검증된 절대 오차가 아니다. |
| 고정 해 수평 산포 | 2DRMS 2 cm 이하 | 기준점이 없거나 좌표 출력 해상도가 판정에 충분하지 않으면 경계 합격을 확정하지 않는다. |
| 차분 나이 | 수신기 차분 나이를 계측해 p50/p95 기록. 합격용 초 단위 한계는 미정. | 기존 age 필드는 전부 빈칸. RTCM byte 속도로 대체하지 않는다. |
| 보정 연속성 | 10분 동안 RTCM byte 증가가 3초 넘게 멈춘 구간 0회 | byte 증가만으로 실제 적용·신선도까지 입증하지 않는다. 최장 무증가 시간과 발생 횟수를 모두 기록한다. |
| 이동 중 fixed | 개활 도로에서 80% 이상 | 기존 주행 기록은 fixed 0%. |
| 장애물 통과 후 재고정 | 중앙 30초 이하 | 장애물 종료 시각과 첫 fixed 시각을 따로 기록한다. 반복 자료가 없으면 개별 시간을 보고한다. |
| 카메라 영향 | fixed+float 비율 차이 20%p 또는 공통 위성·신호의 평균 C/N0 차이 3 dB-Hz는 **강한 영향 단서** 기준 | 10/23 관찰 차이는 약 7.64%p였다. 기준 미만이라고 영향이 배제되지는 않는다. 결과는 ‘재현 단서 있음 / 이번 조건에서 미검출 / 판정 불가’로 나눈다. |

### 기준점·좌표 정밀도

- 10/23 기록의 GGA 좌표는 분 단위 소수 5자리라, 위도 약 1.85 cm·경도 약 1.47 cm 격자로 출력된다(0.00001분 = 1.852 cm, 경도는 cos 37.6°를 곱함). 2 cm·3 cm 목표의 경계 판정은 이 격자 안에서 확정하지 않는다.
- 더 정밀한 출력은 **[승인 필요]** NMEA 고정밀 모드 또는 UBX-NAV-HPPOSLLH.
- 기준점이 있으면 좌표계·기준시기·높이 기준, 기준점 불확도와 안테나 위상중심 맞춤 오차를 함께 기록한다.

### 기준점이 없을 때

- 같은 자리에서 10분 정지해 수평 산포(CEP50·2DRMS)를 계산한다.
- 30분 뒤 같은 자리를 다시 측정해 두 구간의 평균 위치 차이를 기록한다.
- 이 대안은 반복성만 평가한다. 절대 정확도·기준점 오차를 합격으로 판정하지 않는다.
- 참값이 있으면 좌표계·기준시기·타원체고/정표고·안테나 위상중심 높이를 맞춘다.

## 5. 시나리오

### 공통 진행 규칙

- 각 블록 시작·끝과 조건을 바꾼 시각을 초 단위로 기록한다. 표본은 바뀐 직후와 안정 구간을 분리한다.
- **[승인 필요]** 장치에서 수집 시작·중지, 설정 변경, 서비스·파이프라인 재시작, 수신기 메시지·신호 설정, USB/안테나 케이블 탈착, 전원 변경을 하기 전 사용자의 승인을 받는다.
- 변경 전 원래 값·적용 범위·복귀 방법을 비밀 값 없이 PC 기록에 남긴다. 백업에 장치 쓰기가 필요하면 그 동작도 **[승인 필요]**다. 원래 값이나 복귀 방법이 불명확하면 변경하지 않는다. 승인은 한 조작씩 받는다.
- TTFF와 RTK 수렴 시간은 구분한다. 카메라 연결·분리 뒤 첫 30초, 확인된 보정 전달 중단 뒤 첫 2분은 전환 구간으로 별도 보존하고, 안정 구간 비율에서만 제외한다. 재시작·재연결 뒤 수렴 시간은 별도 기록한다.
- 모든 블록에서 앱 화면, `status.json`, `run-*.log`, 수집 `gps.csv`를 가능한 범위에서 같은 시각축으로 맞춘다.

### S0. 시작 점검과 관찰 기준

**목적**: 실외에서 GNSS 표본·보정 경로가 관찰되는지 확인하고, 시작 상태와 관찰 시각을 분리해 기록한다.

**소요 시간**: 약 10분. 수신기 시작·재시작 시각을 모르면 TTFF는 미측정으로 둔다.

**장치 변경·승인 여부**: 읽기 전용 조회만은 승인 불필요. 수집 시작·중지는 **[승인 필요]**.

**사용자가 할 일**

- 안테나를 움직이지 말고 하늘이 열린 곳에 설치한다.
- 현재 카메라·허브·전원 상태를 유지한다.
- 앱의 GNSS 위치 상세와 RTK 요약을 열고 화면 시각을 기록한다.

**Claude가 할 일**

- 현장 관찰 시작 시각, 확인 가능한 수신기 시작·재시작 시각, SSH 상태, status 갱신, NTRIP 연결과 RTCM byte 카운터를 기록한다.
- 현재 보정 경로, 파이프라인 릴리스 식별자, 카메라 릴리스·해상도도 기록한다.
- 이미 fixed인 상태로 첫 관찰을 시작했다면 첫 fixed 시각은 선행한 것으로 표시하고 TTFF는 미측정으로 둔다.

**기록할 값**: 장소, 시각, 안테나 사진·높이, 초기 fix, 위성 수, HDOP, 연결 상태, 공개 마운트포인트 이름, 카메라 모드·릴리스.

**수집 방법**

- 앱의 GNSS 위치 상세에서 위치 품질·위성·고도를 본다. 홈의 RTK 요약은 보조 자료로 쓴다.
- status.json은 갱신 시각·GNSS sample 시각·fix·위성·HDOP·차분 나이·기준국 ID·NTRIP 연결·RTCM byte 누적만 읽는다. 주소·포트·인증 정보·마운트포인트 내부 경로는 출력하지 않는다.
- 실행 로그는 fix 상태, NTRIP 상태, byte 수치와 연결·handover 사건만 추린다. 원문 로그를 공유하지 않는다.
- 수집이 승인돼 있으면 해당 run의 gps.csv에서 raw GGA/RMC와 monotonic 시각을 분석한다.

**판정 방법**

- 수신기 시작·재시작부터 첫 유효 위치까지 시간이 확인될 때만 TTFF로 기록한다.
- 보정 전달 재개 시각이 확인되면 그 시각부터 첫 float와 첫 RTK fixed까지의 시간을 RTK 수렴 시간으로 따로 기록한다.
- status의 파일 갱신만으로 새 GNSS sample을 보장하지 않으므로 sample 시각의 중복·정체·오래됨을 확인한다.

**다음 블록 조건**: 상태·기록 경로와 저장 공간을 확인한 뒤 S1로 간다. SSH가 끊기면 사용자가 시각을 적고 승인된 수집 gps.csv로 사후 판정한다.

### S1. 기준점 정지 시험(현재 설정, 개활지)

**목적**: 현재 설정의 기준 성능, 첫 fixed, 유지율, 기준점 오차와 산포를 측정한다.

**소요 시간**: 첫 관찰 10분. 첫 10분 안에 fixed가 나오면 첫 fixed 뒤 별도 10분을 유지 관찰한다. 600초까지 fixed가 없으면 관찰을 종료하고 미고정으로 기록한다.

**장치 변경·승인 여부**: 현재 설정 유지. 수집 시작·중지와 수집 모드 변경은 **[승인 필요]**.

**사용자가 할 일**

- 기준점에 장비를 고정한다. 측정 중 사람·차량·안테나를 움직이지 않는다.
- 참값이 있으면 기준 좌표·좌표계·기준시기·높이 정보를 제공한다. 없으면 반복성 대안으로 진행한다.

**Claude가 할 일**

- 시작·끝 시각, 첫 float·첫 fixed 시각, 해당 시도에서 관찰한 RTK 수렴 시간을 기록한다.
- 1초 status 기록과 승인된 수집의 raw GGA를 집계한다. GNSS sample이 중복되거나 오래된 status는 새 표본으로 세지 않는다.
- RTCM byte 증가율, 최장 byte 무증가 시간·횟수, NTRIP 사건을 기록한다. 약 2초 간격 로그만으로 짧은 float를 세지 않는다.

**기록할 값**: fix 분포, TTFF(시작 시각을 알 때만), RTK 수렴 시간, 첫 float/fixed, 위성 수 중앙/p90, HDOP 중앙/p90, 보정 age p50/p95 또는 미측정, RTCM byte/s, 좌표·고도, 기준점 오차, CEP50·2DRMS, 관찰률.

**수집·판정 방법**

- 판정 분모는 체크섬이 정상인 raw GGA 관측으로 하고 q0(no fix)도 포함한다. 미인식값·문장 오류·관찰 공백은 따로 기록한다.
- 예정 시간, 전환 제외 시간, 실제 관찰 시간과 관찰률을 함께 적는다. 긴 공백은 직전 fix로 채우지 않는다. 관찰 창을 확보하지 못하면 fixed 비율만으로 합격시키지 않는다.
- 기준점 오차를 계산하기 전에 좌표 원시 정밀도와 저장 반올림을 확인한다. 해상도가 판정에 충분하지 않으면 센티미터 경계 합격은 미확정으로 둔다.
- 이 목표의 중앙·최장 RTK 수렴 시간은 동일 조건의 반복 시도에서만 계산한다. 한 번만 시행하면 그 시도의 개별 시간만 적는다. 미고정 시도를 시간 통계에서 빼지 말고 미고정 횟수와 관찰 종료 시각을 함께 남긴다.
- 기준점이 있으면 수평 오차 p95와 고정 해 2DRMS 목표를 비교한다. 기준점이 없으면 정확도 합격을 선언하지 않고 산포·반복 측정 차이만 적는다.

**다음 블록 조건**: 기준 성능과 자료 파일을 확인한 뒤 S3로 간다. fixed가 없어도 S3를 진행할 수 있지만 조건·보정 상태를 계속 기록한다.

### S3. 카메라·공유 허브 비교

**목적**: 카메라 운용 변화와 USB3·공유 허브의 RF·전력·버스·처리 영향을 구분할 단서를 얻는다. 개별 비교만으로 원인을 확정하지 않는다.

**소요 시간**: S3a 미리보기 A/B/A/B는 5분씩 4구간(20분). S3b도 5분씩 4구간을 권장한다. 선택 S3c·S3d와 재수렴 시간은 별도다.

**장치 변경·승인 여부**: 수집 모드, 카메라 USB 케이블, GNSS·카메라 배치·직결, 차폐재·페라이트, 노트북 연결은 조작마다 **[승인 필요]**. USB 분리로 파이프라인이 재연결을 반복하거나 종료될 수 있다.

**공통 기록**

- 해상도·카메라 릴리스·활성 스트림·실제 USB 링크·전송 상태를 기록한다. 배포 전후 자료는 한 비교에 섞지 않는다.
- 각 A/B 구간은 별도 행(A1/B1/A2/B2)으로 기록한다. 조건 변경 뒤 첫 30초는 전환 구간으로 보존하고 안정 구간 fix 비율에서는 제외한다. 이 시간의 sample 갱신 여부는 따로 확인한다.
- C/N0 비교는 구간 간 공통으로 추적된 같은 위성·같은 신호끼리 한다. GGA 위성 수는 12에서 잘리므로 간섭 판정에 쓰지 않는다.

**비교 순서와 방법**

1. **S3a, 미리보기 상태의 USB 연결·분리 A/B/A/B**: A1 연결 5분 → B1 카메라 USB3 분리 5분 → A2 재연결 5분 → B2 재분리 5분. 각 분리·재연결은 **[승인 필요]**. B1 시작 뒤 첫 30초 동안 GNSS sample 갱신이 계속되는지 확인한다. 갱신이 멈추면 즉시 재연결을 제안하고 이후 분리를 중단한다. B2 뒤 다음 블록으로 가기 전에 카메라를 재연결하고 정상 스트리밍·GNSS 갱신을 확인한다(**[승인 필요]**).
2. **S3b, 운용 모드 전체의 영향 A/B/A/B**: USB·안테나·보정 경로를 유지한다. A1/A2는 RGB+깊이 최대 부하 수집(카메라→Jetson 약 121 MB/s), B1/B2는 RGB 미리보기로 각각 5분 관찰한다. 각 수집 시작·중지 또는 모드 전환은 **[승인 필요]**. 두 모드의 USB 전송량·전력·처리 부하가 다를 수 있으므로 이 비교만으로 처리 부하와 RF를 분리하지 않는다. 실제 링크·스트림 조건을 기록하고 S3a·S3c와 함께 해석한다.
3. **S3c, 배치 대조(선택)**: 가능한 한 안테나 위상중심·방향·접지판은 고정하고 주변 케이블만 바꾼다. ① GNSS 수신기·안테나 케이블을 USB3·허브에서 1~3 m 이격, ② GNSS USB를 허브에서 빼 Jetson 본체 포트에 직결, ③ 승인된 차폐 비교에서 USB3 케이블·허브에 알루미늄 테이프·페라이트 적용. 한 번에 하나씩 3~5분 이상 관찰하고 각 원복·반복도 **[승인 필요]**다. 안테나 위치가 달라지면 다중경로·차폐도 함께 바뀐 것으로 기록한다.
4. **S3d, 노트북 RF 계측(선택)**: 수신기를 사용자 노트북의 u-center에 연결하고 같은 보정 스트림을 노트북에서 유지한다. 이 동안 Jetson은 GNSS를 읽지 못한다. 보정 스트림을 유지한 채 Jetson 카메라 켬/끔을 A/B/A/B로 각각 3~5분 관찰하고, 공통 위성·신호의 C/N0, MON-RF, MON-SPAN과 fix를 기록한다. 수신기 케이블 전환·보정 클라이언트 연결·카메라 전환은 각각 **[승인 필요]**다. NTRIP 계정이 필요한 경우 사용자가 u-center에 직접 입력하고 기록물에 남기지 않는다.

**판정 방법**

- 20%p fix 비율 차이 또는 공통 위성·신호에서 3 dB-Hz C/N0 차이는 강한 영향 단서의 기준이다. 10/23 기록의 복구 구간과 그 밖의 float 비율 차이는 약 7.64%p였으므로 20%p 미만이라고 영향이 배제되지는 않는다.
- 반복 방향이 확인되면 ‘재현 단서 있음’, 통제된 관찰에서 차이가 검출되지 않으면 ‘이번 조건에서 미검출’, 표본 공백·조건 불일치·계측 부족이면 ‘판정 불가’로 기록한다. 미검출을 보편적 원인 배제로 해석하지 않는다.
- 미리보기 상태의 USB 분리에서만 차이가 나면 처리 부하보다 RF·허브 영향 가설이 강해지지만 인과 확정은 아니다. 최대 부하 대 미리보기에서만 차이가 나면 RF·전력·버스·처리 영향을 분리하지 못한 것으로 남긴다.

**다음 블록 조건**: 카메라를 연결한 상태로 복귀시키고 실제 스트리밍·GNSS sample·보정 상태를 확인한 뒤 S2로 간다. 연결 복귀 조작은 **[승인 필요]**다. 해상도 배포가 있었으면 전후 자료를 다른 시험으로 나눈다.

### S2. 보정 비교

**목적**: 보정 부재, 현재 스트림, 실제 관측 메시지가 확인된 대안 사이에 fix·수렴 시간·연속성 차이가 있는지 같은 장소에서 비교한다.

**소요 시간**: 기본 4조건 각 10분. 첫 fixed 뒤 유지율 측정과 재수렴 시간은 별도다. A/B/A/B 반복 비교에는 조건별 반복 구간을 추가한다.

**장치 변경·승인 여부**: 휴대폰 모바일 데이터 변경·복원, 마운트포인트 고정 선택, 보정 경로·설정 변경, 파이프라인 재시작과 별도 UBX 계측은 각각 **[승인 필요]**다. 바꾸기 전 원래 값·적용 범위·복귀 방법을 기록한다. 필요한 원복을 확인할 수 없으면 변경하지 않는다.

**사전 확인**

- S3 뒤 같은 기준점에 장비를 둔다. 당일 보정 경로가 폰 중계인지 장치 직접 경로인지 읽어서 기록한다.
- 장치 파이프라인 릴리스에 `rtcmSignals` 기록이 들어 있으면 S2에서 실제로 들어온 신호를 그 기록으로 확인한다. 반영 전후 결과는 섞지 않는다.
- 보정 없음 비교 전에 실제 경로가 폰 중계인지 확인한다. 모바일 데이터 차단으로 보정 전달이 중단되지 않으면 보정 없음 조건으로 판정하지 않는다.
- SSH도 끊길 수 있는 구성에서는 수집을 먼저 시작하고 새 gps.csv와 실행 로그가 생성·갱신되는지 확인한다. 차단·복원 시각은 사용자가 기록한다.

**Claude가 할 일**

- 각 구간의 시작·끝, 실제 공개 마운트포인트, 연결·byte 증가·무증가, 첫 float·첫 fixed와 RTK 수렴 시간을 기록한다.
- 수신기 적용 여부·보정 나이가 계측되지 않으면 미확인으로 둔다. RTCM byte 증가만으로 적용을 추정하지 않는다.

**조건별 절차**

1. **현재 설정 A1, 10분**: 자동 선택 설정과 실제 선택된 공개 마운트포인트·보정 경로를 기록한다. 앱 중계 등록과 장치의 payload byte 증가를 구분한다.
2. **보정 없음, 10분**: 현재 경로가 폰 중계이고 모바일 데이터 차단으로 전달을 끊을 수 있을 때만 시행한다. 모바일 데이터 끄기와 복원은 각각 **[승인 필요]**다. 실제 RTCM 전달 중단을 확인한 뒤 첫 2분은 잔여 보정 가능 구간으로 따로 표시한다. 전달 중단을 입증하지 못하면 ‘차단 여부 확인 필요’로 남긴다.
3. **현재 보정 재개 A2, 10분**: 모바일 데이터 복원은 **[승인 필요]**다. byte 전달이 확인된 시각부터 첫 float·첫 fixed까지 RTK 수렴 시간으로 잰다. 600초까지 fixed가 없으면 관찰 종료까지 미고정으로 기록한다. 10분 안에 fixed가 나오면 fixed 유지율은 그 뒤 별도 10분 창에서 계산한다. 수신기를 재시작하지 않는다.
4. **대안 보정 B1, 10분**: 계정이 있으면 RTS-3 MSM7 단일 기준국 중 당일 가장 가까운 곳이 1순위, 없으면 `ICOR-RTCM32`다. 공개 소스테이블에서 RTS-3(`rts3.ngii.go.kr:2101`, 네트워크 `NGII-GVRS`)는 단일 기준국 301개가 RTCM 3.2 MSM7 1077(GPS)·1097(Galileo)·1127(BeiDou)을 광고하며 GGA는 필요 없고 Basic 인증 계정이 필요하다. 10/23 위치 기준 가장 가까운 표기는 `Seoul-Gangseo-Gaehwa` 약 1 km, `Seoul-Seongbuk-Seongbuk` 16.5 km, `Gimpo-Yangchon` 18.8 km, `Paju-Paju` 21.9 km다. 좌표가 0.1° 단위라 거리는 근사치이며 당일 위치에서 다시 고른다. 계정은 사용자가 장치 보호 설정에 직접 입력하고 Claude는 계정을 다루지 않는다. 실제 수신 메시지·공통 신호를 확인하지 못하면 비교는 미실시/확인 필요로 둔다. 기준국이 L5·E5a·B2a를 보내면 수신기와 이중 주파수 공통 신호가 생길 가능성은 있으나 미확인이다. RTS-3 계정이 없으면 ICOR-RTCM32(10/23 위치 약 25 km), 다음 SWGS-RTCM32(약 41 km)를 후보로 삼되 실제 메시지·신호가 확인될 때만 비교하며 장거리 결과는 10 km 이내 정상 성능 판정과 분리한다. 고정 선택·설정 변경·재시작은 **[승인 필요]**다.
5. **반복 대조(시간·조건이 허용될 때)**: 대안 비교는 현재 스트림 A2 → 대안 B1 → 현재 스트림 A3 → 같은 대안 B2의 순으로 반복한다. 각 구간은 10분이며 실제 stream·장소·초기 상태를 맞춘다. 현재 스트림과 대안을 오가는 설정 변경은 매번 **[승인 필요]**다. 같은 조건을 유지하지 못하거나 한 번씩만 비교하면 탐색 결과로만 기록하고 원인 판정을 보류한다.
6. **선택 비교: RTS-1 보정**: `rts1.ngii.go.kr:2101`의 `RTK-RTCM32`는 GGA를 보내면 캐스터가 가까운 기준국을 고르고, `VRS-RTCM34`도 있다. 둘 다 소스테이블 표기상 GPS 1004+MAC(1014~1016)뿐이므로 L1 한계 가능성이 크다. 계정이 있을 때만 별도 비교 후보로 기록한다.
7. **선택: 장치 직접 경로 대 폰 중계**: 같은 마운트포인트·장소·수신 조건을 유지할 수 있을 때만 비교한다. 경로 전환은 **[승인 필요]**이며 같은 stream을 유지할 수 없으면 비교 불가로 기록한다. 계정·비밀 값·내부 주소·포트는 출력하거나 기록하지 않는다.
8. **선택 계측**: 실제 메시지 종류·신호 마스크와 수신기의 사용 여부를 확인하려면 별도 UBX 출력 또는 노트북 계측이 필요하다. **[승인 필요]** 전용 계획과 승인 없이는 수행하지 않는다.

**판정 방법**

- 보정 없음은 전달 중단이 확인된 구간만 판정한다. fix quality 2가 남았다는 사실만으로 SBAS 등 특정 원인을 확정하지 않는다.
- 대안에서 개선돼도 실제 메시지와 공통 신호가 확인되기 전에는 형식 변경과의 연관으로만 기록한다.
- 연결·byte가 있는데 fixed가 없으면 수신기 적용·epoch age를 미확인으로 남긴다.
- 비교 중 실제 stream이 바뀌면 구간을 분리한다. 같은 조건의 반복이 없거나 시작 상태가 다르면 중앙·최장값으로 일반화하지 않는다.

**다음 블록 조건**: S2 자료와 설정 상태를 기록한 뒤 S4로 간다. 대안 후보나 실제 메시지를 확인할 수 없으면 해당 비교를 미실시/확인 필요로 기록하고, 확인되지 않은 상태로 설정을 바꾸지 않는다.

### S4. 개활지와 건물 근처(차폐·다중경로)

**목적**: 같은 장비·보정·카메라 조건에서 하늘 가림에 따른 품질 차이를 본다.

**소요 시간**: 각 구간 10분, 반복 A/B/A/B는 총 4구간. 위치 이동·재수렴 시간은 별도다.

**장치 변경·승인 여부**: 시험 장비를 지점 사이로 이동하는 단계는 **[승인 필요]**. 설정은 바꾸지 않는다.

**사용자가 할 일**

- A1 개활지 → B1 건물 근처 → A2 개활지 → B2 건물 근처 순으로 반복한다. 시간이 부족해 A/B만 하면 탐색 결과로 표시한다.
- 가능한 한 안테나 높이·방향·차량 상태와 보정·카메라 조건을 같게 맞춘다.
- 건물·나무·차량 지붕 등 가림 방향, 건물 거리와 사진을 남긴다.

**Claude가 할 일**

- 지점 이동·관찰 재개 시각, 첫 float·fixed, 실제 보정 stream과 sample 공백을 기록한다.
- 이동 중 stream이 바뀌면 구간을 나누고 A/B 원인 판정을 보류한다.

**기록할 값**: 지점·가림 방향, fix 비율, 첫 float/fixed, HDOP·위성, 고도·좌표 산포, 기준점 오차, RTCM byte/s, 관찰률.

**수집·판정 방법**: 앱·1초 status와 승인된 gps.csv를 같은 시간축에 정렬한다. 건물 근처에서 no-fix/float 증가 또는 산포 확대가 반복되면 장소 효과 단서로 기록한다. C/N0·잔차가 없으면 다중경로와 안테나 차폐를 확정적으로 나누지 않는다.

**다음 블록 조건**: 두 장소 결과를 저장한 뒤 S5로 간다. 장비·보정·카메라 조건이 달라졌으면 그 비교는 판정 불가로 표시한다.

### S5. 이동 시험(주행)

**목적**: 개활 도로의 fixed 유지율, 장애물 통과 후 재고정 시간, 자동 handover를 본다.

**소요 시간**: 경로 1회 왕복과 필요한 정차 구간. 도로·교통에 맞춰 현장에서 정한다.

**장치 변경·승인 여부**: 주행 중 설정 변경·재시작은 하지 않는다. 이동 중 장치·케이블 조작도 하지 않는다.

**사전 관문**

- S2에서 마운트포인트를 고정 선택해 두었다면 자동 선택·handover가 활성인지 읽어서 확인한다. 수동 선택이 남아 있으면 자동 handover는 미시험으로 기록한다. 원래 자동 선택으로 돌리는 설정 변경이 필요하면 이전 값·복귀 방법 확인 후 **[승인 필요]**를 받는다.
- 경로·정차 장소, 카메라·안테나·보정 상태를 출발 전에 기록한다.

**사용자가 할 일**

- 개활 구간, 나무·건물·고가 구조물 아래, 개활 구간을 포함한 안전한 경로를 고른다.
- 운전자는 휴대폰을 만지지 않는다. 동승자가 시각·장애물 구간을 기록한다.
- 안전한 곳에 정차할 수 있으면 장애물 통과 전후 시각을 표시한다.

**Claude가 할 일**

- raw GGA/RMC의 fix·속도·시간을 정렬한다. 이동 점은 정지 산포에 섞지 않는다.
- handover 시작·완료, NTRIP byte·연결 상태와 공백을 사건 시각으로 기록한다.
- 자동 전환은 관찰만 한다. 가까운 마운트포인트를 강제로 바꾸지 않는다.

**기록할 값**: 경로·속도, 장애물 시작·끝, fix 비율, no-fix·float 길이, 장애물 종료부터 첫 fixed까지 시간, handover 사건, RTCM 무증가 시간·횟수, 관찰 공백.

**판정 방법**: 개활 도로 fixed 비율 80% 이상, 장애물 뒤 재고정 중앙 30초 이하를 목표로 한다. 반복 시도 자료가 없으면 중앙값 대신 개별 시간을 기록한다. handover 전후는 이동 위치와 실제 stream을 함께 기록하되 단순 전후 비율만으로 stream 효과를 단정하지 않는다.

**다음 블록 조건**: 안전하게 종료하고 로그·CSV를 저장했으면 선택 S6 또는 원래 상태 복귀로 간다.

### S6. 선택: 안테나 위치·접지판 비교

**목적**: 안테나 설치·하늘 시야·접지판이 품질에 미치는 영향을 비교한다.

**소요 시간**: 위치별 10분 권장. 첫 fixed가 늦으면 계획한 관찰 상한에서 미고정으로 기록하고 재수렴 시간은 별도로 남긴다.

**장치 변경·승인 여부**: 안테나·케이블·접지판을 움직이거나 교체할 때마다 **[승인 필요]**. GNSS USB를 분리하면 fix 재획득에 시간이 걸릴 수 있다.

**사용자가 할 일**: 먼저 현재 위치를 사진·치수로 남긴다. 승인된 비교에서 안테나 위치나 접지판 중 한 항목만 바꾸고 각 변경 시각을 기록한다.

**Claude가 할 일**: 같은 위치·보정·카메라 조건인지 확인하고 변경 시각, 재수렴, fix·HDOP·산포를 기록한다.

**기록할 값**: 안테나 모델·방향·높이·접지판, 케이블 길이·경로·USB3와 거리, fix·C/N0 계측 여부, 기준점 오차.

**다음 블록 조건**: 비교를 마치면 안테나·접지판·케이블을 원래 위치로 되돌리고 복귀를 확인한다. 각 원복은 **[승인 필요]**다.

### 마지막. 원래 상태로 되돌리기와 확인

- 설정 변경 전 원래 값, 적용 범위(휘발성/영구 저장 여부), 복귀 방법을 비밀 값 없이 PC 기록에 남긴다. 백업 때문에 장치 쓰기가 필요하면 그 동작도 **[승인 필요]**다. 원래 값이나 복귀 방법이 불명확하면 변경을 시작하지 않는다.
- **[승인 필요]** 바꾼 설정·마운트포인트 선택·휴대폰 모바일 데이터·카메라 모드·USB 배치·안테나 위치를 변경 기록과 대조해 하나씩 원복한다. 휴대폰 모바일 데이터 복원도 포함한다.
- 파이프라인 재시작 또는 수신기 설정 변경을 원복에 사용해야 하면 그 조작 전에 별도 **[승인 필요]**를 받는다. 수신기 초기화를 원래 설정 복원과 동일시하지 않는다. 실행 명령은 이 계획서에 적지 않는다.
- status 갱신, GNSS sample, NTRIP 연결 및 RTCM byte 증가를 읽어 원래 동작 경로로 돌아왔는지 확인한다.
- 마지막 사진과 상태를 시작 전 기록과 비교한다. 승인되지 않은 추가 조작은 하지 않는다.

**기록 시 주의**

- fix 분포는 체크섬이 정상인 raw GGA 기준이며 q0도 분모에 포함한다. 미인식값·오류·관찰 공백은 별도로 적는다. 시간 가중 비율을 주 지표, 표본 비율을 보조로 두고 관찰 공백을 직전 fix로 채우지 않는다.
- 예정 시간, 전환 제외 시간, 실제 관찰 시간과 관찰률을 함께 적는다. 공백 때문에 목표 창을 확보하지 못하면 fixed 비율만으로 합격시키지 않고 재시험 또는 판정 불가로 둔다.
- status 표본 시각의 중복·역행·오래됨을 확인한다. 최상위 status 갱신만으로 새 GNSS 관측을 보장하지 않는다.
- 기준점 오차·산포를 계산할 때 원시 좌표 정밀도, 저장 반올림, 기준점 불확도와 안테나 중심 맞춤 오차를 적는다. 좌표가 없는 status 기록만으로 산포를 계산하지 않는다.
- 보정 나이 필드가 비거나 계측 경로가 없으면 미측정이라고 적는다. 0으로 채우지 않는다. 최장 RTCM 무증가 시간과 횟수도 평균 byte/s와 별도로 기록한다.
- 위성 수는 GGA 12개 상한 때문에 주 판정에 쓰지 않는다. 위치 원문·민감 문자열·내부 주소나 포트가 포함된 로그를 표에 붙이지 않는다.

#### status.json whitelist

다음 코드는 장치의 status JSON을 읽고 허용된 필드만 출력한다. mountpoint 문자열, 주소, 인증값은 출력하지 않는다.

```sh
python3 - <<'PY'
import json, time
from pathlib import Path
p = Path('/var/lib/jetson-sensors/status.json')
d = json.loads(p.read_text())
g = d.get('gnss', {})
keys = ('configured','connected','active','lastSampleAtEpochMillis',
        'fixQuality','fixType','fixName','rtkStatus','satellites','hdop',
        'altitudeM','differentialAgeS','referenceStationId',
        'ntripConnected','rtcmBytes')
print(json.dumps({'readAtEpochMillis': int(time.time()*1000),
                  'updatedAtEpochMillis': d.get('updatedAtEpochMillis'),
                  'gnss': {k: g.get(k) for k in keys},
                  'mountpointPresent': bool(g.get('ntripMountpoint'))},
                 ensure_ascii=False))
PY
```

1초마다 PC에 이력을 남길 때는 위 whitelist를 기존 SSH 경로에서 반복 읽고, 출력만 Claude가 쓰는 PC의 시험 기록(JSONL 등)에 저장한다. `/var/lib/jetson-sensors/status.json` 자체는 덮어쓰기 파일이므로 장치에 새 기록 파일을 만들지 않는다.

#### RTK 로그에서 숫자·사건만 추출

현재 실행 주체에 맞춰 센서 모니터와 파이프라인 journal, 실제 run 로그를 확인한다. 주소·포트·계정·마운트포인트가 포함된 원문은 출력하지 않는다. 아래는 읽기 전용 예시다.

~~~sh
journalctl --since '30 minutes ago' -o short-iso --no-pager |
python3 -c '
import re,sys
for s in sys.stdin:
    if not any(k in s for k in ("RTK NTRIP","rtcm_bytes=","gps_fix=","gps serial")): continue
    out=[]
    for name,rx in (("fix",r"gps_fix=(\d+)"),
                    ("rtcmBytes",r"rtcm_bytes=(\d+)"),
                    ("ntripState",r"ntrip=(connected|connecting)"),
                    ("closerKm",r"([0-9.]+)km closer")):
        m=re.search(rx,s)
        if m: out.append(name+"="+m.group(1))
    for event,label in (("validating handover","handover_start"),
                        ("seamless handover complete","handover_done"),
                        ("switching after error","candidate_switch"),
                        ("gps serial reconnecting","serial_reconnect"),
                        ("RTK NTRIP connected","ntrip_connected")):
        if event in s: out.append("event="+label)
    if out:
        stamp=s.split()[0]
        print(stamp," ".join(out))
'
~~~

수집 로그를 읽을 때는 자리표시자를 실제 파일명으로 바꾸기 전에는 실행하지 않는다. 경로 전체를 따옴표로 감싼다. 실행 로그에 시각이 없으면 time=미기록으로 두고 journal과 대조하며, 첫 토큰을 시각으로 간주하지 않는다.

### B. 계산 방법

- **Fix 비율**: 체크섬이 정상인 raw GGA만 사용하고 q0를 포함한다. fix quality별 시간 가중 비율을 주 지표, 표본 수 비율을 보조로 기록한다. 미인식값·문장 오류·관찰 공백은 별도 집계한다.
- **관찰률**: 예정 시간, 전환 제외 시간, 실제 관찰 시간과 공백을 기록한다. 긴 공백을 직전 fix로 채우지 않는다. 목표 창을 확보하지 못하면 fixed 비율만으로 합격시키지 않는다.
- **TTFF**: 수신기 시작·재시작부터 첫 유효 항법 위치까지다. 시작 시각을 모르면 미측정이다. 관찰 첫 표본에서 이미 위치가 있으면 시작 전 획득으로 기록하고 시간을 추정하지 않는다.
- **RTK 수렴 시간**: 확인된 보정 전달 재개부터 첫 float 및 첫 RTK fixed까지 각각 잰다. 끝까지 fixed가 없으면 600초 관찰 종료까지 미고정으로 기록한다. fixed 이후 유지율은 별도 10분 창으로 계산한다. 중앙·최장은 동일 조건 반복에서만 산출하고, 단일 시행은 개별 시간과 미고정 횟수를 보고한다.
- **HDOP**: 유효 숫자만 모아 중앙값과 p90을 계산한다. 99.99 같은 no-fix sentinel은 정상 DOP로 섞지 않는다.
- **보정 나이 분위수**: 실제 differentialAgeS 또는 승인된 UBX 계측만 사용해 p50/p95를 계산한다. 값이 없으면 미측정이다. rtcmBytes 증가량과 혼동하지 않는다.
- **RTCM byte/s·무증가 구간**: 같은 카운터의 구간 끝-시작 차이를 경과 초로 나눈다. counter reset·handover·재시작은 분리한다. 무증가 최장 시간과 횟수를 따로 기록한다. byte 수치는 수신기 적용 확인이 아니다.
- **수평 산포**: 기준점이 없을 때 구간 평균 위치를 원점으로 지역 동·북 좌표를 만들고 CEP50과 2DRMS를 계산한다. fix 종류·정지 구간별로 나누고 자기상관 표본을 독립 측정 횟수처럼 해석하지 않는다.
- **기준점 오차**: 참값과 같은 좌표계·기준시기·안테나 위상중심 높이를 적용한 뒤 수평 거리 오차 p95를 낸다. 원시 좌표 해상도와 저장 반올림이 목표 판정에 영향을 주면 경계 합격은 확정하지 않는다. 타원체고와 정표고를 혼용하지 않는다.
- **장애물 후 재고정**: 장애물 구간 종료부터 첫 fix_quality=4까지 잰다. 보정 재개 후 RTK 수렴 시간과 구분한다.
- **분위수 표기**: p50은 중앙값, p90/p95는 해당 백분위 값이다. 빠진 값은 0이 아니라 미측정이다.
