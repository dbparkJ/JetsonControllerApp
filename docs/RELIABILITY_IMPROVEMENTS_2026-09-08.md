# 2026-09-08 연결 안정성 개선 기록

기준 문서: [2026-09-05 검토 및 개선방향](JetsonControllerApp_검토_및_개선방향_2026-09-05.md). 기존 `main`의 문서를 먼저 커밋·푸시하고 별도 작업 브랜치에서 수정했다. 작업 시작 시 GitHub 원격에는 `main`만 있어 별도로 가져올 미통합 브랜치가 없었다.

## 반영 내용

| 항목 | 구현 |
|---|---|
| CON-01 | Jetson 외부 명령 시간 초과를 연결 오류로 통합. 시도 ID·단조 시계 120초 시한, 늦은 성공 차단, 종료된 연결 작업 복구. 그룹·DHCP·일반 Wi-Fi 정리 실패를 오류 상태로 보존. |
| CON-02 | Android 타임아웃·취소·해제 시 OS 협상 취소와 대상 그룹 제거. 최대 8초 정리 단계 동안 새 시도 차단. 다른 그룹 보호, 이전 세대 콜백 무시. |
| CON-03 | 등록 장비별 `장비에 직접 연결` 진입점과 공유기·업로드 중단 영향 확인. 명시적 Direct 선택을 자동 LAN 탐색보다 우선하며, 사용자가 Wi-Fi를 설정하면 LAN 전환을 다시 허용. |
| CON-04 | 연결 시도 ID와 활성 제어 세션 ID를 `TransportCoordinator`에서 별도로 관리. BLE 준비 완료가 진행 중인 IP 검사를 취소하지 않도록 수정. 연결 전이 처리를 Android 메인 디스패처에서 직렬화. |
| NET-01 | 백엔드 상태를 별도 루프에서 수집하고 API는 캐시 스냅샷 반환. 동기 시스템 명령·파일 처리를 작업 스레드로 이동하고 파이프라인·RTK 변경 잠금 보강. 앱 hello/status/capabilities는 전체 8초·읽기 6초, IP 확인 시도 전체는 20초 제한. 큰 파일의 기존 제한 유지. |
| STATE-01 | 상태·제어 응답의 장비/세션/요청 순서 검사. 이전 상태 실패도 현재 실패 횟수에 반영하지 않음. 명령 전송 결과는 완료를 단정하지 않고 장비 수락으로 안내. 파일·팬·작업·업로드 등 IP 기능 응답은 세션 변경 시 폐기. |
| UX-01 | 일시 끊김으로 화면을 연결 허브로 되돌리지 않음. 장비별 작업 초안, 설정 편집값, 파일 탐색 경로, 업로드·Wi-Fi 입력 맥락 보존. 오프라인 변경 작업 차단, 재연결 후 설정 revision/반영 여부 재조회. |
| UX-02 | 등록·발견·기본 연결·제어 가능·정리 중을 구분. 오프라인 앱 설정과 업로드 이력 진입 허용. 장비 전환 시 이전 확인 대화상자 폐기. |
| DATA-01 | 기존 스칼라·BLE 형식에 `collectedAtEpochMillis`와 `metricValidity`를 추가. 측정 실패는 확인 불가, 오래된 값은 이전 측정 시각을 표시하고 건강 판정에서 제외. |
| OPS-01 | 연결 운영 문서 갱신. 빌드·lint·선택 회귀 테스트용 GitHub Actions 추가. 앱 버전 `1.15.2` (`21`). |

## 검증

- Android 코드 커밋: `592345f`, 백엔드 코드 커밋: `592d192`.
- APK SHA-256: `6f2b4edb231cfade52abc3ca9662b7d6211d43c7ea0430924487a443b8957466`.

- 백엔드 Wi-Fi Direct·상태·API 관련 63개 테스트 통과. 잠금 변경 관련 파이프라인·모바일 RTK 21개 테스트 통과. 최종 Wi-Fi/상태 보강 후 관련 37개를 재확인했다.
- Android `assembleDebug` 성공, 연결 세션·자동 정책·화면 보존·측정 표시 관련 9개 클래스 33개 단위 테스트 통과. `lintDebug`는 오류 0개·경고 69개로 완료했다. 첫 병렬 lint 실행의 내부 분석기 오류는 `--max-workers=1` 실행으로 해결했고 CI도 같은 옵션을 적용했다. 최종 APK는 마지막 화면 변경을 반영해 다시 빌드했다.
- 무선 디버깅 기기: Galaxy S22 Ultra (`SM-S908N`), Android 16, `111.111.111.192:37869`. 기존 설치 버전 `1.15.1` (`20`)에서 데이터 유지 설치(`adb install -r`)로 `1.15.2` (`21`) 갱신 완료. `am start -W` 결과 `Status: ok`, COLD 실행 825ms. 실행 프로세스 로그에 FATAL/ANR 표식 없음. 실제 연결 허브에서 발견됨/등록됨, 장비별 직접 연결, 오프라인 앱 설정·업로드 기록 진입점 표시를 확인했다.
- 무선 디버깅 전송 중 간헐적인 `No route to host`/offline이 관측됐고 재연결 후 설치·실행을 완료했다. 실제 Direct 전환으로 휴대전화 네트워크를 바꾸는 추가 시험은 하지 않았다.
- 로컬 기본 ADB 1.0.39가 무선 디버깅을 처리하지 못해 저장소 SDK Platform Tools 37.0.1을 사용했다. ARM64 개발 호스트에서는 기존 QEMU와 SDK 실행 환경을 활용했다.

## 범위와 남은 현장 검증

이번 변경은 문서의 구체적인 결함과 복구 흐름을 우선한 안정화다. 전체 홈 정보 구조 재설계, 기능별 Repository 전체 분리, 권한 요청 시점 전면 개편은 포함하지 않았다.

초안·탐색 맥락은 앱 프로세스가 유지되는 동안 장비별로 보존한다. 앱 강제 종료·프로세스 회수 후 복원하는 영속 초안 기능은 추가하지 않았다. 기존 BLE 패킷에는 지표별 유효성을 실을 필드가 없어 새 측정 메타데이터는 HTTPS API에 적용된다.

Jetson 서비스의 실제 배포·재시작, 실장비 외부 명령 시간 초과 주입, 여러 어댑터 조합의 반복 연결, 장시간 RTK/업로드 검증은 수행하지 않았다. 사용자의 테스트 최소화 요청에 따라 반복 연결 50회 등의 검증은 생략했다. 백엔드 개선은 이 저장소의 갱신된 서비스를 Jetson에 배포한 뒤 적용된다.
