# JetsonControllerApp 제품 정의

기준일: 2026-09-14
적용 기준: `main@e41b752a72be4e5367c1108ab32a2725c8fb4dec`와 2026-09-14 멀티 에이전트 작업 세트

## 1. 제품 목적

JetsonControllerApp은 자전거 도로 조사 현장에서 Android 휴대전화 또는 태블릿으로 한 대의 Jetson 장비를 선택해 수집 작업을 시작·감시·종료하고, 결과가 Jetson과 수신 서버에 남았는지 단계별로 확인하는 운영 도구다.

제품이 해결해야 할 핵심 문제는 원격 명령 전송 자체가 아니다. 현장 작업자가 다음 질문에 근거를 가지고 답할 수 있어야 한다.

1. 어느 프로젝트의 어느 조사 구간에서 어떤 작업을 실행하는가?
2. 지금 수집을 시작해도 되는가?
3. 연결이 끊겨도 Jetson의 수집은 계속되고 있는가?
4. 종료 후 결과가 Jetson에 저장되었는가?
5. 서버가 그 결과를 완전하게 수신했는가?
6. Jetson과 연결되지 않은 상태에서도 휴대전화 인터넷으로 같은 서버 결과를 확인할 수 있는가?

## 2. 사용자와 운영 경계

| 사용자 | 주 책임 | 허용 범위 |
|---|---|---|
| 현장 작업자 | 장비 연결, 프로젝트·구간·작업 선택, 시작 점검, 수집 감시, 종료, 저장·수신 확인 | 검증된 일반 작업 흐름 |
| 운영 관리자 | 장비·작업 등록, 서버 대상·정책 관리, 진단, 복구와 보관 | 관리자 인증과 권한이 확인된 범위 |
| 개발자·정비 담당자 | 로그, 터미널, 설정, 장애 조사 | 일반 사용자 흐름과 분리된 도구 |
| 인간 PM | 필수 센서, 품질 임계값, 프로젝트 권한, 운영 합격 결정 | 미결 정책의 최종 승인 |

한 번에 제어하는 장비는 사용자가 명시적으로 선택한 한 대다. 화면이 바뀌거나 연결 경로가 LAN과 Wi-Fi Direct 사이에서 바뀌어도 선택 장비의 identity가 일치하지 않으면 명령을 보내지 않는다.

## 3. 도메인 계약

제품의 업무 단위는 다음 계층으로 정의한다.

```text
프로젝트(Project)
└─ 조사 구간(Section)
   └─ 작업 정의(Task / Pipeline)
      └─ 실행(Run)
         ├─ 실행 메타데이터와 로그
         ├─ 경로·품질 구간
         ├─ Jetson 출력 세션
         └─ 서버 업로드 세션과 검증
```

- **프로젝트**: 발주·운영 단위. 이름만이 아니라 안정적인 `projectId`가 필요하다.
- **조사 구간**: 실제 조사 범위. `sectionId`, 표시 이름, 프로젝트 소속을 가진다.
- **작업 정의**: Jetson에 등록한 수집 프로그램과 실행 설정. 현재 코드의 `ManagedPipeline`과 대응한다.
- **실행**: 시작부터 종료까지 한 번의 수집. 재연결이나 앱 재시작 때문에 새 실행으로 중복 생성하면 안 된다.
- **Jetson 출력 세션**: 실행 결과가 저장된 장치 측 경로와 파일 집합.
- **서버 업로드 세션**: 수신 서버가 발급한 `sessionId`와 검증된 파일 집합.

현재 기준선에는 작업 정의와 실행의 최소 모델은 있으나 프로젝트·조사 구간 entity와 실행에 대한 영속 연결은 없다. 이 항목은 핵심 제품 계약이며 선택 기능이 아니다. 7개 작업의 현재 소유 범위에 구현 담당이 명시되어 있지 않으므로 통합 단계에서 별도 구현 owner를 지정하기 전까지 **운영 출시 차단 항목**으로 관리한다.

| PM-005 | 시작 점검 | 장비 identity, 작업 선택, 저장 가능성, 시간, 필수 센서, 위치/RTK 정보 상태를 보여 준다. 인간 PM이 필수로 정하지 않은 항목은 경고로 표시하되 임의의 합격 임계값을 만들지 않는다. |

| PM-007 | 이중 보관 증거 | Jetson 저장 확인과 서버 수신 확인은 서로 대체할 수 없다. 각각 별도의 상태와 증거를 유지한다. |
| PM-008 | 서버 수신 완료 | 업로드 작업 `COMPLETED`, receiver verification `matched=true`, 동일한 `remoteSessionId`의 합계/해시 증거가 일치해야 한다. 확인 실패 상태를 완료로 표시하지 않는다. |
| PM-009 | 서버 직접 조회 | Jetson proxy 조회와 휴대전화 인터넷을 통한 receiver 직접 조회를 구분한다. 운영 완료 흐름은 후자를 포함한다. |
| PM-010 | 부분 성공 | 로컬 수집은 끝났지만 업로드가 남았거나, 명령 반영 가능성이 있으나 응답이 유실됐거나, receiver 수신 후 독립 조회가 안 되는 경우를 부분 성공/확인 필요로 표현한다. |
| PM-011 | 데이터 보존 우선 | 오류·연결 단절·품질 저하만으로 원본을 자동 삭제하지 않는다. 원본 삭제는 수신 검증과 명시적 사용자 확인 이후에만 가능하다. |
| PM-012 | 재부팅 후 시작 | 재부팅 자동 재시작은 설정 가능성을 남기되 기본값은 실제 상태 확인 후 사람이 시작하는 정책이다. |
| PM-013 | 품질 판단 | RTK FIX 비율이나 필수 센서 합격 임계값은 근거와 인간 PM 승인이 있을 때만 pass/fail로 사용한다. 승인 전에는 측정값·문제 구간·경고만 제공한다. |
| PM-014 | 사용자 영역 | 현장 작업 화면과 관리자/개발자 기능을 정보 구조와 권한으로 구분한다. |
| PM-015 | 삭제 경험 | 일반 목록 제거는 복구 가능한 soft-delete, Undo, 휴지통/복원을 기본 계약으로 한다. 영구 삭제는 별도 확인과 권한이 필요하다. |

## 5. 공통 상태 의미

모든 화면과 API 조합은 다음 세 범주를 같은 뜻으로 사용한다.

| 분류 | 의미 | 표시와 다음 행동 |
|---|---|---|
| 정상 | 기대한 최종 상태를 대상에서 다시 관찰했고 식별 가능한 증거가 있다. | 완료 상태, 관찰 시각, 장비/실행/세션 식별자를 보여 준다. |
| 오류 | 대상이 요청을 거절했거나 `FAILED`, 불일치, 필수 점검 실패 같은 확정 오류를 반환했다. | 실패 원인과 안전한 복구 행동을 보여 준다. 이전 성공 증거는 보존한다. |
| 부분 성공 / 확인 필요 | 앞 단계는 성공했지만 다음 단계가 남았거나, 요청 적용 여부를 관찰하지 못했다. | 확인된 범위와 미확인 범위를 함께 표시하고 상태 재조회 후 재시도한다. |

`오프라인`, `조회 실패`, `응답 시간 초과`는 그 자체로 작업 실패가 아니다. 마찬가지로 업로드 전송 바이트가 100%여도 receiver 검증이 끝나지 않았다면 서버 수신 완료가 아니다.

## 6. 단계별 완료 증거

| 단계 | 정상 완료 증거 | 부분 성공 또는 확인 필요 | 오류 |
|---|---|---|---|
| 연결 | 선택한 `deviceId`와 인증된 endpoint가 일치하고 지원 기능을 조회함 | BLE 기본 연결만 가능하거나 endpoint 전환 중 | identity/TLS/HMAC 불일치, 인증 거절 |
| 프로젝트·구간 | 유효한 `projectId`, `sectionId`, 표시 이름과 권한 확인 | 캐시만 있고 서버 최신성 미확인 | entity 없음, 권한 거절 |
| 작업 선택 | 선택 구간에 사용할 `pipelineId`와 release/config 정보 확인 | 작업은 있으나 설정/버전 확인 필요 | 작업 없음 또는 등록 오류 |
| 시작 점검 | 점검 항목별 관찰값과 시각, blocker 없음 | 승인되지 않은 품질 기준 경고 또는 선택 센서 문제 | identity, 저장공간, 필수 센서 등 승인된 blocker 실패 |
| 시작 | 동일 `pipelineId`가 `RUNNING`으로 관찰되고 새 `runId/logId`가 연결됨 | 요청 이후 응답 유실, `STARTING`, 실행 identity 미확인 | 명시적 시작 실패 또는 `FAILED` |
| 수집 | 실행이 `RUNNING`, 로그/경로/품질 관찰 시각 갱신 | 연결 단절 또는 일부 telemetry 미수신 | Jetson이 실제 `FAILED`/종료를 보고 |
| 연결 복구 | 같은 장비에 재인증 후 실제 실행과 보류 명령을 재조정 | 일부 상태만 회복 | 다른 장비 identity 또는 인증 실패 |
| 종료 | 실행 비활성 상태, `finishedAt`, 종료 결과와 로그 확인 | 중지 요청 결과 유실/`STOPPING` | 명시적 stop 실패 또는 실행 `FAILED` |
| Jetson 저장 | 실행과 연결된 출력 root/path가 존재하고 기대 파일/합계를 조회 | 실행은 끝났으나 출력 연결 또는 스캔 진행 중 | 경로 없음, 읽기/무결성 오류 |
| 서버 수신 | 업로드 `COMPLETED`, 검증 `matched=true`, 동일 `remoteSessionId` | queued/scanning/uploading, 검증 대기, receiver 독립 확인 대기 | upload `FAILED`, 검증 불일치 |
| 서버 직접 조회 | 휴대전화가 receiver에 직접 인증해 동일 session/files/verification 조회 | 캐시만 표시되며 마지막 성공 시각이 명시됨 | 인증/권한 실패, session 불일치 |

| RTK 품질 요약 | 모바일 중계와 route는 있으나 FIX 비율/문제 구간 계약은 없음 | AG06 |
| soft-delete/Undo/휴지통 | 구현되지 않음 | AG02 UX + AG05 복구 API. 미지원 범위는 성공 표시 금지 |

## 8. 제품 합격 단계

### 시연 합격

시연 합격은 통제된 시험 장비·계정·네트워크에서 대표 흐름을 한 번 이상 재현하고 단계별 증거를 저장했다는 뜻이다. 최소 조건은 다음과 같다.

- 지정 Jetson에 연결하고 올바른 장비 identity를 표시한다.
- 테스트용 프로젝트·구간 context를 명확히 기록한다. entity가 아직 구현되지 않았다면 시연 한계로 표시한다.
- 작업 시작, 진행, 종료의 실제 상태와 단일 실행 identity를 확인한다.
- Jetson 출력 경로와 서버 upload session/verification을 확인한다.
- receiver 직접 조회를 수행한다.
- 한 번의 연결 단절과 복구 시나리오에서 중복 실행이 생기지 않는다.

### 현장 운영 합격

현장 운영 합격은 시연 합격보다 강하다. 실제 지원 장치와 운영 인증으로 반복 시험하고 데이터 손실·잘못된 장비 제어·인증 문제에 대한 release blocker가 없어야 한다.

- 프로젝트·구간 entity, 직원 역할, 프로젝트 권한이 실제 운영 저장소와 연결된다.
- 휴대전화와 태블릿, Orin NX 지원 matrix의 필수 조합을 통과한다.
- 잠금, 일시 단절, LAN/Wi-Fi Direct 전환, 장시간 수집, 저장공간 부족, 서버 불가, 재시작/복구를 검증한다.
- 수집 원본, Jetson 저장 증거, 서버 검증, 직접 조회가 동일 실행에 추적된다.
- 승인된 필수 센서와 품질 정책이 적용되며 임의 임계값이 없다.
- 진단, rollback, 운영 책임자와 장애 대응 절차가 준비된다.

자동 단위 테스트와 로컬 빌드 통과는 필요한 개발 증거지만 시연 또는 현장 운영 합격 자체가 아니다.
