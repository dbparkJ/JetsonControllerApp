# GEO& 현장 기능

GEO& 도로관리장치 제어 1.16.0은 기존 Slate 색상·장비 인증·업로드 방식을 유지한다. 앱을 새로 실행하거나 백그라운드에 30분 이상 머문 후 복귀할 때 1.6초 동안 브랜드 시작 화면이 표시된다. 구성 변경으로 Activity가 다시 생성될 때는 시작 화면을 반복하지 않는다. 홈·설정에 사용하는 사진은 사용자가 제공한 합성 장치 사진이다.

## 화면과 작업 기록

홈은 장치 사진과 CPU·GPU·온도를 상단에 표시한다. 미수신·오래된 상태는 현재 측정값처럼 표시하지 않는다. 작업은 전체·진행 중·대기·완료로 구분된다. 전체에는 최근 10회가 표시되고 완료 탭에서 이전 기록을 더 불러올 수 있다. `+`에서 실행 프로그램을 선택하고 한 단계 안쪽에서 새로운 작업을 등록한다. 완료 탭에는 완료 외에 중지·실패·결과 미확인도 정확한 상태 이름으로 표시한다.

기록은 `/var/log/jetson-pipelines/<pipeline-id>/run-*.log`에서 구성되어 앱 종료·재연결 후에도 장치에 남는다. 기존 로그도 읽을 수 있고 등록 해제 후에도 남은 로그는 조회된다. 완료 footer가 없는 과거 기록은 성공으로 추정하지 않는다. 작업별 기존 로그 보관 한도는 20개/1GiB이며 경로도 해당 로그와 함께 정리된다.

새 실행의 경로는 로그 옆 `.route.jsonl` 파일에 기록된다. 휴대전화가 잠기거나 연결이 끊겨도 장치의 실행기가 기록한다. 위치 권한은 휴대전화 위치 마커에 적용되며 장치 GNSS 기록과 별개다. GPS가 유효하지 않은 구간은 선을 이어 만들지 않는다. 한 실행의 경로 파일 한도는 8MiB다. 이전 버전 실행에는 경로가 없으며 소급 생성하지 않는다.

## 데이터와 서버

데이터 탭은 장치 파일 목록을 우선 보여준다. 이미지·영상·센서·로그 필터와 오늘·어제·날짜별 그룹은 현재 폴더의 항목에 적용된다. 폴더는 각 필터에서 계속 탐색할 수 있다. 날짜는 휴대전화 시간대로 표시하며 시간이 없으면 `날짜 미확인`으로 분리된다. 폴더 전체 및 개별 파일 전송을 지원하고 이미지 미리보기에서 핀치·더블 탭·버튼 확대/축소를 유지한다.

이미지 목록의 썸네일은 화면에 보이는 셀에서 가져오며 동시 요청 2개, 표시용 다운샘플링을 적용한다. 16MiB를 초과하는 파일 또는 디코딩 불가능한 포맷은 이미지 아이콘으로 표시된다. 원본 전송에는 영향을 주지 않는다.

서버 보관함은 **Jetson API가 서버 인증을 중계하는 기존 구조**다. 장치 연결이 없으면 서버 데이터를 직접 가져올 수 없으며 화면에 연결 필요를 표시한다. 서버 설정 새로고침 시 현재 대상 목록을 다시 읽고, 구버전 대상 응답에 `type`이 빠져도 HTTP 서버가 필터에서 사라지지 않는다. 실제 인증 실패·수신 서버 미설치 등은 오류로 표시된다.

## 캡처와 개발자 옵션

실시간 카메라 화면의 캡처 버튼에서 장치, 모바일 또는 두 위치를 선택한다. 장치는 `recordings` 저장 루트 아래 `captures/GEO_<UTC>.jpg`, 모바일은 갤러리 `Pictures/GEO&/`에 저장한다. 두 곳 저장 시 하나의 장치 프리뷰 프레임을 사용한다. 장치 성공·모바일 실패는 별도로 표시된다. 캡처는 원본 센서 촬영 요청이 아니라 현재 프리뷰 JPEG 저장이다.

설정의 빌드 번호를 5초 이상 간격을 두지 않고 7번 누르면 개발자 옵션이 열린다. 개발자 모드 스위치로 다시 끌 수 있다. 원격 터미널은 기존 장치 인증으로 단일 `/bin/sh -lc` 명령을 실행하며 대상 장치를 확인하는 화면을 거친다. `pipeline_user`로만 실행하고 root 사용자는 거부한다. systemd의 파일 접근 제한은 그대로 적용된다. 최대 15초·출력 64KiB·장치당 동시 1개이며 지속 SSH 세션이나 대화형 TTY는 아니다. 명령 응답 유실 시 자동 재실행하지 않는다. 저장된 작업 로그와 앱 진단 로그를 개발자 옵션에서 열 수 있다.

## 장치 업데이트와 검증 범위

앱 설치와 장치 백엔드 업데이트는 별개다. 실행 기록·경로·장치 캡처·원격 터미널은 이 버전의 전체 `backend/jetson_control` 패키지와 `run-pipeline.py`를 장치에 설치해야 한다. 예전의 일부 진단 파일만 교체하는 배포는 이 기능 배포 경로가 아니다. 기존 [백엔드 설치·운영](BACKEND.md)의 전체 설치가 사용된다. `recordings` 루트가 API 서비스의 쓰기 허용 경로에 포함되어 있어야 장치 캡처가 가능하다.

이번 작업은 실제 장치가 없는 상태이므로 수집·시작/중지·원격 명령·실제 서버 전송·센서/GPS/카메라 저장의 장치 수용 검증을 수행하지 않는다. 자동화된 모의 API/회귀검사와 휴대전화 화면 검증은 별도로 기록한다.

모바일 저장은 Android의 [공유 미디어 저장소](https://developer.android.com/training/data-storage/shared/media)의 `IS_PENDING` 게시 절차를 사용한다. 지도 경로는 기존 MapLibre 지도에 [PolylineOptions](https://maplibre.org/maplibre-native/android/api/-map-libre%20-native%20-android/org.maplibre.android.annotations/-polyline-options/index.html)를 연결한다.
