# GEO& 현장 기능

GEO& 도로관리장치 제어 1.16.1은 기존 Slate 색상·장비 인증·업로드 방식을 유지한다. 앱을 새로 실행하거나 백그라운드에 30분 이상 머문 후 복귀할 때 1.6초 동안 브랜드 시작 화면이 표시된다. 구성 변경으로 Activity가 다시 생성될 때는 시작 화면을 반복하지 않는다. 홈·설정에 사용하는 사진은 사용자가 제공한 합성 장치 사진이다. 시작 화면·장치 연결·홈의 로고는 제공된 투명 `images/logo.png`를 사용한다. 좁은 헤더에서는 이미지 안의 작은 영문 문구를 제외하고 화면 제목을 읽기 쉬운 글씨로 표시한다. 어두운 배경에서는 로고 문자를 밝은 색으로 표시한다. 앱 아이콘은 GEO 색상의 지도·위치 심벌로 표시한다. 본문·보조 글씨와 장치 선택 이름을 키우고 상단 영역은 글자 크기에 따라 높이가 늘어나도록 배치한다.

LAN 재접속은 마지막으로 인증에 성공한 주소를 앱 재실행 후에도 기억한다. 장치 검색이 다른 네트워크의 주소를 반환하고, 저장된 주소가 현재 휴대전화 네트워크에 속하며 포트가 같을 때만 재사용한다. 재접속 때에도 기존 TLS·장치 인증을 수행한다.

## 화면과 작업 기록

홈은 장치 사진과 CPU·GPU·온도를 상단에 표시한다. 미수신·오래된 상태는 현재 측정값처럼 표시하지 않는다. 홈 탭을 누르면 대시보드 첫 화면으로, 작업 탭을 누르면 실행 프로그램 선택 첫 화면으로 이동한다. 이전 하위 화면을 자동 복원하지 않는다. `작업 시작`을 누르면 현재 연결과 작업 상태를 새로 조회하는 최종 점검 창이 열린다. 점검 성공 후 `확인 후 시작`을 눌러야 시간 동기화와 시작 요청이 실행된다. 새 작업 등록은 선택 화면의 `+`에서 연다.

실행 기록은 선택 화면의 `작업 이력`에서 모두 조회한다. 전체·진행 중·완료 필터와 이전 기록 더 불러오기를 제공하며 완료 탭에는 중지·실패·결과 미확인도 실제 상태로 표시한다. 기록 카드를 오른쪽으로 밀면 삭제 확인창이 열린다. 카드 아래의 별도 삭제 버튼은 없으며, 스크린 리더에서는 `작업 이력 삭제` 접근성 동작을 사용한다. 확인 후 해당 실행의 로그와 경로만 삭제한다. 수집 원본 데이터와 등록된 실행 프로그램은 유지한다. 실행 중인 최신 기록은 장치에서도 삭제를 거부한다.

기록은 `/var/log/jetson-pipelines/<pipeline-id>/run-*.log`에서 구성되어 앱 종료·재연결 후에도 장치에 남는다. 기존 로그도 읽을 수 있고 등록 해제 후에도 남은 로그는 조회된다. 완료 footer가 없는 과거 기록은 성공으로 추정하지 않는다. 작업별 기존 로그 보관 한도는 20개/1GiB이며 경로도 해당 로그와 함께 정리된다.

새 실행의 경로는 로그 옆 `.route.jsonl` 파일에 기록된다. 휴대전화가 잠기거나 연결이 끊겨도 장치의 실행기가 기록한다. 위치 권한은 휴대전화 위치 마커에 적용되며 장치 GNSS 기록과 별개다. GPS가 유효하지 않은 구간은 선을 이어 만들지 않는다. 한 실행의 경로 파일 한도는 8MiB다. 이전 버전 실행에는 경로가 없으며 소급 생성하지 않는다.

## 데이터와 서버

장치·서버 데이터 삭제 및 작업 이력 삭제의 완료 알림은 잠시 표시된 뒤 자동으로 닫힌다. 닫기 버튼으로 즉시 닫을 수도 있으며, 화면을 나갔다 돌아와도 지난 완료 알림을 반복하지 않는다.

데이터 탭은 장치 파일 목록을 우선 보여준다. 이미지·영상·센서·로그 필터와 오늘·어제·날짜별 그룹은 현재 폴더의 항목에 적용된다. 폴더는 각 필터에서 계속 탐색할 수 있다. 날짜는 휴대전화 시간대로 표시하며 시간이 없으면 `날짜 미확인`으로 분리된다. 폴더 전체 및 개별 파일 전송을 지원하고 이미지 미리보기에서 핀치·더블 탭·버튼 확대/축소를 유지한다.

이미지 목록의 썸네일은 화면에 보이는 셀에서 가져오며 동시 요청 2개, 표시용 다운샘플링을 적용한다. 16MiB를 초과하는 파일 또는 디코딩 불가능한 포맷은 이미지 아이콘으로 표시된다. 원본 전송에는 영향을 주지 않는다.

서버 보관함은 **Jetson API가 서버 인증을 중계하는 기존 구조**다. 장치 연결이 없으면 서버 데이터를 직접 가져올 수 없으며 화면에 연결 필요를 표시한다. 서버 설정 새로고침 시 현재 대상 목록을 다시 읽고, 구버전 대상 응답에 `type`이 빠져도 HTTP 서버가 필터에서 사라지지 않는다. 실제 인증 실패·수신 서버 미설치 등은 오류로 표시된다.

## 캡처와 개발자 옵션

실시간 카메라 화면의 캡처 버튼에서 장치, 모바일 또는 두 위치를 선택한다. 장치는 `recordings` 저장 루트 아래 `captures/GEO_<UTC>.jpg`, 모바일은 갤러리 `Pictures/GEO&/`에 저장한다. 두 곳 저장 시 하나의 장치 프리뷰 프레임을 사용한다. 장치 성공·모바일 실패는 별도로 표시된다. 캡처는 원본 센서 촬영 요청이 아니라 현재 프리뷰 JPEG 저장이다.

설정의 빌드 번호를 5초 이상 간격을 두지 않고 7번 누르면 개발자 옵션이 열린다. 개발자 모드 스위치로 다시 끌 수 있다. 원격 터미널은 기존 장치 인증으로 단일 `/bin/sh -lc` 명령을 실행하며 대상 장치를 확인하는 화면을 거친다. `pipeline_user`로만 실행하고 root 사용자는 거부한다. systemd의 파일 접근 제한은 그대로 적용된다. 최대 15초·출력 64KiB·장치당 동시 1개이며 지속 SSH 세션이나 대화형 TTY는 아니다. 명령 응답 유실 시 자동 재실행하지 않는다. 저장된 작업 로그와 앱 진단 로그를 개발자 옵션에서 열 수 있다.

## 장치 업데이트와 검증 범위

앱 설치와 장치 백엔드 업데이트는 별개다. 실행 기록·경로·장치 캡처·원격 터미널은 이 버전의 전체 `backend/jetson_control` 패키지와 `run-pipeline.py`를 장치에 설치해야 한다. 예전의 일부 진단 파일만 교체하는 배포는 이 기능 배포 경로가 아니다. 기존 [백엔드 설치·운영](BACKEND.md)의 전체 설치가 사용된다. `recordings` 루트가 API 서비스의 쓰기 허용 경로에 포함되어 있어야 장치 캡처가 가능하다.

이력 삭제는 인증된 `DELETE /v1/task-runs/{pipeline_id}/{log_id}` 요청과 `{"confirmed":true}` 본문을 사용한다. API 서비스의 `ReadWritePaths`에 `/var/log/jetson-pipelines`를 포함해야 한다. 기존 설치에는 서비스 설정도 함께 적용한다.

2026-09-12 검증 당시에는 실제 장치가 없어 수집·시작/중지·원격 명령·서버 전송·센서 저장의 장치 수용 검증을 수행하지 않았다. 아래는 당시의 검증 기록이다.

모바일 저장은 Android의 [공유 미디어 저장소](https://developer.android.com/training/data-storage/shared/media)의 `IS_PENDING` 게시 절차를 사용한다. 지도 경로는 기존 MapLibre 지도에 [PolylineOptions](https://maplibre.org/maplibre-native/android/api/-map-libre%20-native%20-android/org.maplibre.android.annotations/-polyline-options/index.html)를 연결한다.

### 1.16.0 검증 기록 (2026-09-12)

2026-09-12 기준 Android APK·테스트 APK 빌드, Lint, JVM 200개, 휴대전화의 통신 없는 Compose 화면 검사 3개가 통과했다. 라이트/다크 시작 화면, 실행 상태 필터·추가 버튼, 날짜/유형 필터와 파일·폴더 전송 콜백을 확인했다. 색상 검사에서는 66개 토큰 및 94개 대비 조합이 통과했다.

Python 3.11 모의검사 238개는 실패 없이 완료되었고 기존 환경 조건에 따른 2개가 건너뛰어졌다. 별도로 DBus/GLib이 필요한 기존 BLE 모듈 2개는 해당 가상환경에서 실행할 수 없어 전체 실행 목록에서 제외했다. 마지막 프리뷰 가용성·GPS 공백 보완 후 관련 API/실행기/경로 검사 47개도 통과했다. 실제 Jetson 작업·장치 캡처·서버 파일 수용시험은 사용자 요청대로 수행하지 않았다.

SM-S908N 휴대전화에 `versionName=1.16.0`, `versionCode=23`을 기존 데이터 유지 방식으로 설치했다. 검증 APK SHA-256은 `805bc23e5bbeb0d068613fb74afd6c4c5df6a9b9f03e1409f090af4a4621889e`다. 휴대전화 설치가 장치 백엔드 배포를 의미하지 않는다.
