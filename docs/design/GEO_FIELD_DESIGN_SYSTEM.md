# GEO& Field System

현장 수집·장치 제어 앱의 디자인 시스템. 2026-09-15 기준.

> 이 문서는 **구현된 토큰과 컴포넌트**를 설명합니다. 이 브랜치의 코드가 정본이고
> 문서는 그 해설입니다. 값이 서로 다르면 `ui/theme/` 를 따르세요.
>
> **이 브랜치는 컴파일 검증을 거치지 않았습니다.** 작성 환경에서 Android SDK·Gradle
> 배포본·Google Maven에 접근할 수 없어 `kotlinc` 문법 검사까지만 수행했습니다.
> 리뷰 전에 `./gradlew assembleDebug` 와 계측 테스트를 반드시 실행하세요.

---

## 0. 이 시스템이 해결하려는 것

제품 브리프가 던지는 네 가지 질문이 디자인의 전부입니다.

> 어느 장치를 조작하고 있나? → 지금 수집해도 되나? → 수집이 실제로 진행 중인가?
> → 끝난 자료가 어디에, 어떤 상태로 남아 있나?

시스템의 모든 결정은 이 질문에 답하는지로 평가합니다. **가장 비싼 오독은
'연결됨'을 '저장됨'으로 읽는 것**이고, 그다음은 **'미확인'을 '성공' 또는 '실패'로
읽는 것**입니다. 앞의 것은 조사를 잃게 하고, 뒤의 것은 중복 실행을 만듭니다.

## 1. 컬러

### 1.1 브랜드

승인된 GEO& 기업 로고(`images/logo.png`)에서 직접 추출했습니다.

| 역할 | HEX | 출처 |
|---|---|---|
| Brand 500 (기본) | `#2550A3` | 워드마크 블루 |
| Sky 500 / 400 | `#2A86C7` / `#69BDEA` | 지구본 중간톤·하이라이트 |
| Navy 700 | `#32366A` | 지구본 그림자, 다크 테마 히어로 |
| Brand Green | `#29674E` | 앰퍼샌드 `&` |

**앰퍼샌드 그린은 브랜드 액센트로만 씁니다.** 메인 테마 색이 아니고, 상태색
'정상'으로도 재사용하지 않습니다. 정상 상태는 별도의 `#0F6B4F` 계열을 쓰고,
이 둘은 화면에서 동시에 등장하지 않도록 사용처를 분리했습니다.

앱 아이콘의 밝은 블루(`#18ACFD`–`#0059DC` 그라디언트)는 **런처 아이콘에만**
있습니다. 48dp에서 한 번 읽히는 아이콘과 한 시간 동안 햇빛 아래에서 읽히는 UI
표면은 요구 조건이 다릅니다.

### 1.2 상태 6축

이 시스템의 핵심입니다. `StatusTone` 은 여섯 값을 가집니다.

| 토큰 | 의미 | 라이트 전경 | 다크 전경 | 대표 문구 |
|---|---|---|---|---|
| `SUCCESS` | 확인됨 — 장치나 서버가 실제로 응답한 결과 | `#0F6B4F` | `#6FD3A7` | 저장 확인됨, 수신 검증 완료 |
| `WARNING` | 주의 — 제한을 알고 진행 가능 | `#8A5300` | `#F2BE68` | 선택 센서 경고, LAN 전환 필요 |
| `ERROR` | 차단·실패 — 시작할 수 없거나 실제로 실패 | `#B3261E` | `#FF9E95` | 필수 조건 미충족, 전송 실패 |
| `INFO` | 안내 — 판정이 아닌 맥락 | `#1F4489` | `#8FAEE4` | 점검 전, 선택 필요 |
| `PENDING` | 처리 중 — 요청은 접수됐고 결과는 열려 있음 | `#574AA6` | `#B7ACEF` | 시작 요청 중, 중지 요청 중, 검증 중 |
| `UNKNOWN` | 미확인 — 모른다 | `#515967` | `#AAB4C1` | 시작 결과 미확인, 값 오래됨, 캐시 목록 |

`PENDING` 과 `UNKNOWN` 이 이 개편의 실질입니다. 이전 시스템에는 네 개의 톤밖에
없어서 "시작 결과 미확인"이 성공·경고·안내 중 하나로 흘러들어갔습니다.

- `UNKNOWN` 을 성공으로 읽으면 → 조사가 안 돌고 있는데 자리를 뜹니다.
- `UNKNOWN` 을 실패로 읽으면 → 잘 돌고 있는 실행 위에 두 번째를 시작합니다.

그래서 `UNKNOWN` 은 의도적으로 **채도가 없는 중립 슬레이트**입니다. 좋지도
나쁘지도 않게 보이는 것이 정확한 표현입니다.

### 1.3 이전 팔레트에서 무엇이 잘못됐나

`Slate Harmony V7` 의 문제는 취향이 아니라 구조였습니다.

```kotlin
// 이전
success = Color(0xFF525862)   // ← muted 와 같은 회색
muted   = Color(0xFF525862)
successBg = Color(0xFFEBEEF1) // ← subtle 과 같은 배경
```

`success` 와 `muted` 가 **같은 값**이었습니다. "저장 확인됨" 배지와 비활성 보조
텍스트가 화면에서 구별되지 않았고, 다크 테마에서도 `success = #B5BBC5` 로 같은
문제가 반복됐습니다. 색만 바꿔서는 고칠 수 없고, 상태의 의미 축 자체를 다시
정의해야 했습니다.

### 1.4 대비 검증

모든 조합을 WCAG 2.x 상대 휘도로 계산해 검증했습니다. 라이트·다크 각각 24개 쌍
전부 통과합니다. 최초 계산에서 세 쌍이 미달해 값을 조정했습니다.

| 조합 | 조정 전 | 조정 후 | 기준 |
|---|---|---|---|
| 라이트 비활성 라벨 | 3.88 | **4.63** | 4.5 |
| 라이트 입력 테두리 | 2.95 | **3.18** | 3.0 |
| 다크 비활성 라벨 | 4.33 | **4.66** | 4.5 |

비활성 라벨은 WCAG 상 면제 대상이지만 기준을 적용했습니다. 이 제품은 시작 버튼을
**활성화하는 경우보다 비활성화하는 경우가 훨씬 많고**, 그때마다 사용자는 왜
못 누르는지를 읽어야 하기 때문입니다.

## 2. 타이포그래피

플랫폼 산세리프를 유지합니다. 대상 기기에서 Roboto + Noto Sans KR 폴백으로
해석되며, 이것이 폰트를 번들하지 않고 얻을 수 있는 가장 안정적인 한글 렌더링입니다.

| 스타일 | 크기/행간 | 용도 |
|---|---|---|
| `headlineSmall` | 21 / 30 | 화면 제목, 다음 행동 제목 |
| `titleMedium` | 17 / 26 | 섹션 제목 |
| `titleSmall` | 15 / 22 | 목록 항목 제목 |
| `bodyLarge` | 17 / 27 | 본문 |
| `bodyMedium` | 15 / 24 | 설명 |
| `bodySmall` | 13 / 20 | 보조 |
| `labelLarge` | 15 / 20 | 버튼 |
| `GeoType.numeric` | 17 / 24 · tnum | 갱신되는 값 |
| `GeoType.numericLarge` | 26 / 32 · tnum | 한눈에 읽는 대표 수치 |
| `GeoType.identifier` | 13 / 19 · mono | Run ID, 점검 ID, 경로, 해시 |
| `GeoType.eyebrow` | 12 / 16 | 섹션 제목 위 한 줄 |

**고친 것**

- 이전 스케일은 `bodyLarge` 와 `bodyMedium` 이 **둘 다 16/24** 였습니다. 본문과
  강조 본문이 같은 값이라 중간 단계가 없었습니다.
- 행간을 폰트 크기의 약 1.45배로 올렸습니다. 한글은 같은 크기에서 라틴보다 넓은
  행간이 필요합니다.
- **숫자는 tabular figures 를 씁니다.** 이전에는 비례 숫자라 19% → 20% 로 값이
  바뀔 때 행 전체가 흔들렸습니다. 브리프의 "갱신 때 레이아웃이 심하게 흔들리지 않게"
  요구가 이것입니다.
- Run ID·점검 ID는 모노스페이스입니다. 장식이 아니라 **한 글자씩 대조해서 읽어야
  하는 값**이기 때문입니다.

## 3. 간격 · 반경 · 크기

`GeoSpace` 는 4dp 단위의 엄격한 스케일이고, 단계마다 이름이 하나뿐입니다.

```
xs 4 · sm 8 · md 12 · lg 16 · xl 20 · xxl 24 · xxxl 32 · huge 40
gutter 20 (화면 좌우 여백) · section 24 (섹션 간) · row 12 (섹션 내부 행 간)
```

이전 `AppSpacing` 은 `large = 16` 과 `screen = 20` 이 의미상 겹쳐서, 두 화면이
같은 토큰을 쓴다고 주장하면서 다르게 보일 수 있었습니다.

`GeoRadius`: `xs 6 · sm 10 · md 14 · lg 18 · xl 24`

이전 `medium 20 / large 24 / extraLarge 28` 에서 크게 줄였습니다. 과하게 둥근
표면은 소비자용 앱으로 읽히고, 모든 행의 네 모서리를 낭비합니다. 이 제품은
"전문적이지만 복잡하지 않음"을 지향하고 밀도 높은 상태 정보를 담아야 합니다.

`GeoSize`

| 토큰 | 값 | 근거 |
|---|---|---|
| `minTouchTarget` | 48dp | **Android 공식 최소 기준** |
| `primaryAction` | 56dp | **프로젝트 제안 기준** — 서서 조작하는 시작·중지·전송 |
| `secondaryAction` | 48dp | 보조 동작 |
| `statusDot` | 8dp | 배지의 색맹 대응 중복 신호 |
| `statusRule` | 3dp | 섹션 선단의 상태 색 규칙 |

**48dp는 플랫폼 기준이고 56dp는 이 프로젝트의 제안입니다.** 브리프가 요구한 대로
둘을 섞지 않고 토큰 이름과 주석에서 구분했습니다.

## 4. 컴포넌트

### 4.1 상태 표현

**`StatusBadge(label, tone)`** — 색 + 점 + 문구를 항상 함께 렌더링합니다.
흑백 스크린샷, 색각 이상, 직사광선 아래에서도 의미가 남아야 합니다. 야외에서는
색상 분리가 형태 분리보다 훨씬 먼저 무너집니다.

**`GeoStatusTile(title, value, detail, tone, freshness)`** — 현장 홈의 독립
상태 축 하나. 배경을 물들이지 않고 아이콘과 값에만 색을 씁니다. 타일 네 개가
색 블록으로 나란히 서면 아무 문제가 없을 때도 화면이 위태로워 보이고, 정작 진짜
경고가 묻힙니다.

**`AppBanner(message, tone, actionLabel, onAction, onDismiss)`** — 대상 옆에
붙는 인라인 메시지. 토스트가 아닙니다. 판단이 필요한 문제는 설명과 다음 행동을
달고 화면에 남아 있어야 합니다.

**`GeoStateBlock(title, impact, tone, primaryLabel, ...)`** — 빈 화면·실패·미확인.
`impact` 가 **선택 인자가 아니라 필수 인자**입니다. 사용자의 업무에 어떤 영향이
있는지 말하지 않는 오류 메시지는 사용자가 건너뛰는 법을 배우는 메시지입니다.

### 4.2 구조

**`GeoSection(tone, content)`** — 관련 내용 묶음. 그림자나 톤 틴트가 아니라
평면 표면 + 헤어라인 테두리로 구분합니다. 그림자는 야외에서 사라지고, 톤 틴트는
"올라온" 표면을 기본색 쪽으로 끌어당겨 상태색과 싸웁니다. `tone` 을 넘기면
섹션 선단에 상태 색 규칙이 그려집니다 — **배경은 물들이지 않습니다.**

**`GeoDataRow(label, value, valueUnavailable)`** — 라벨/값 한 쌍. 값은 tabular,
그리고 `valueUnavailable` 은 대시가 아니라 명시적으로 **"미확인"** 을 찍습니다.
값이 없는 것과 값이 0인 것은 다른 사실입니다.

**`GeoFreshnessLabel(text, stale)`** — "마지막 확인 · 12:03". 방금 가져오지 않은
값을 보여줄 수 있는 화면에는 반드시 하나 있어야 합니다.

**`DeviceContextHeader`** — 어느 장치를 조작 중인지에 대한 상시 답. 장치 이름은
누를 수 있는 컨트롤이고, 연결 상태는 배지로 명시합니다. 높이를 고정하지 않아
시스템 글꼴 200%에서도 잘리지 않습니다.

### 4.3 동작

**`GeoBottomActionBar(readiness, readinessTone, content)`** — 주 행동이 왜
가능하거나 불가능한지를 한 줄로 말합니다. 이전 설계는 조용히 비활성화해서
사용자가 이유를 추측해야 했습니다. 내비게이션 바 인셋을 스스로 처리합니다 —
이 프로젝트가 실기에서 이미 한 번 고쳤던 회귀 지점입니다.

**`GeoPrimaryAction(label, onClick, enabled, icon)`** — 56dp.

**`GeoDangerAction(label, target, onClick)`** — `target` 이 어느 장치의 어떤
작업에 영향을 주는지 말합니다. 확인 다이얼로그 안이 아니라 **버튼 옆에** 있어야
사용자가 제스처를 커밋하기 전에 읽습니다.

## 5. 다크 · 태블릿 · 접근성

**다크는 반전이 아닙니다.** 라이트·다크가 같은 의미의 토큰을 각자의 값으로 정의
합니다. 다크에서 상태색은 채도를 낮추고 명도를 올려 과하게 빛나지 않게 했습니다.

**너비는 기기가 아니라 창 기준입니다.** `GeoBreakpoint.medium = 600dp`,
`expanded = 840dp` 를 **앱 창 크기**에 대해 측정합니다. 폴더블에서 창을 줄이면
좁은 레이아웃이 나와야 합니다.

**접근성**

- 터치 대상 48dp 이상, 주 행동 56dp.
- 모든 상태는 색 + 아이콘/형태 + 문구.
- 아이콘에는 목적을 알 수 있는 `contentDescription`.
- 스와이프 등 제스처만으로 수행해야 하는 필수 동작 없음.
- 식별자는 `contentDescription` 으로 통째 읽히게 처리.

## 6. 문구 규칙

**현재 무슨 일인지 → 사용자 작업에 어떤 영향이 있는지 → 다음에 무엇을 할 수 있는지.**

| 상황 | 톤 | 문구 | 행동 |
|---|---|---|---|
| 장치 연결 단절 | `UNKNOWN` | 장치 연결이 끊겼습니다. 마지막으로 확인한 수집 상태를 표시하고 있습니다. | 다시 연결 |
| 시작 응답 유실 | `PENDING` | 시작 요청의 결과를 확인하지 못했습니다. 새 작업을 시작하기 전에 현재 실행을 확인해 주세요. | 실행 결과 확인 |
| 필수 센서 미수신 | `WARNING` | 필수 센서 IMU의 상태를 확인하지 못했습니다. 연결을 점검한 뒤 다시 확인해 주세요. | 다시 점검 |
| Wi-Fi Direct에서 전송 시도 | `WARNING` | 현재 연결에서는 서버 전송을 시작할 수 없습니다. Jetson을 LAN으로 연결해 주세요. | 연결 방법 보기 |
| 원본 저장만 완료 | `SUCCESS` | 장치에 저장됐습니다. 서버에는 아직 전송하지 않았습니다. | 전송 준비 |
| 서버 검증 중 | `PENDING` | 파일 전송이 끝났습니다. 서버에 정상적으로 도착했는지 확인하고 있습니다. | 수신 상태 보기 |
| 캐시 목록 | `UNKNOWN` | 마지막으로 동기화한 자료입니다. 현재 서버 상태와 다를 수 있습니다. | 새로고침 |

**금지**

- 근거 없는 '연결 완료' / '검증 완료'
- '완료' 하나로 실행 종료 + 저장 확인 + 서버 수신을 뭉뚱그리기
- 실제 API가 제공하지 않는 진행률·예상 시간·정확도를 채워 넣기
- 오래된 프리뷰나 센서 값에 LIVE 표시

## 8. 아직 확정하지 않은 것

브리프가 "협의 필요"로 남긴 항목은 디자인에서 임의로 정하지 않았습니다.

- 상태 최신성 임계값(몇 초부터 "오래됨"인가)
- 필수 센서 정책과 시작 차단 기준
- RTK 합격 기준
- 휴지통 보관 기간과 영구 삭제 허용 범위
- 장갑 사용 빈도, 실제 거치 방식, 주 사용 화면 방향, 태블릿 기종

시스템은 이 값들이 정해졌을 때 **표현할 자리**를 마련해 뒀습니다
(`GeoFreshnessLabel`, `checkTone`, `GeoDangerAction`). 값 자체는 개발·운영
계약에서 가져와야 합니다.
