# GEO-X R7 스타일 가이드

작성: 2026-10-25 · 기준 프레임 412 × 882dp · 앱 Pretendard / HTML 시안 Noto Sans KR

## 1. 방향과 보존 범위

사진으로 장치를 구별하고, 큰 숫자로 판단하며, 진한 현재 작업 카드에서 다음 행동을 찾는다. 정보의 풍부함은 사진·지도·영상·숫자 크기·면의 높낮이·여백으로 만든다. 색은 행동과 실제 상태에만 사용한다.

R6의 01–20과 같은 장치·자료·문구·행동·상태를 보존한다. 19는 01의 GRAPHITE, 20은 06의 NAVY_DARK 변형이다. 시작·인라인·실패 L1–L3을 추가한다. R6/SPEC-R6.md의 거래, 권한, 수신 증거, 위험 동작 확인 규칙을 상속한다. HTML은 정적 검토 시안이며 기능을 실행하지 않는다.

## 3. 색 사용 규칙

유일한 원본은 `D:/JetsonController/docs/design/colors.json`의 `color.STANDARD`, `NAVY_LIGHT`, `HIGH_CONTRAST`, `GRAPHITE`, `NAVY_DARK`, `MIST`와 `fixed`다. 새 hex, tile*, work* 역할을 만들지 않는다. Android ARGB 8자리만 CSS RGBA로 순서 변환한다. 원본 사진·로고의 내장 픽셀은 수정하지 않는다. 지정 좌표의 무손실 자르기와 어두운 면에서 워드마크만 text 단색으로 그리는 처리는 §5를 따른다.

- 바탕: canvas, surface, sunken, field. 글자: text, textSecondary, textSubtle.
- 주 행동 한 계열: primary / onPrimary, 선택: primaryTint / primaryTintText. 선택하지 않은 빠른 기능은 모두 중립.
- success는 연결·수신·응답·정밀 위치 등 확인된 상태, warning은 지연·미연결·기준 초과, danger는 실패·불일치·종료/전원 등 위험 행동, pending은 보고 대기·수신 미확인, neutral은 대기·오프라인에만 사용한다.
- 상태의 반복은 작은 점과 문구로 제한한다. 성공 행 전체를 초록으로 채우지 않는다. 실제 경고·실패 묶음만 warningSoft / dangerSoft.
- 지표 숫자는 정상 범위에서 text. 기준 초과 때만 상태색과 원인을 함께 표시한다.
- 지도 구역·정밀 경로·대략 경로·미확인·관찰 공백·장치·휴대폰·casing은 `fixed.map*` 그대로 사용한다. 예시 지도의 지면·건물은 기존 중립 역할을 사용한다. 지도와 도로 영상은 R6와 같은 설계용 SVG 자료이며 실제 타일·영상이 아니다.
- 외부 게시 페이지의 page* 장식 토큰도 같은 원본 색을 재사용하되 앱 역할과 검수에서 구분한다.

### 진한 현재 작업 카드 — 화면당 최대 1개

| 팔레트 | 카드 면 / 기본 글자 | 주 행동 면 / 글자 | 의도 |
|---|---|---|---|
| STANDARD·NAVY_LIGHT·HIGH_CONTRAST | inverse / onInverse | inverseAction / inverse | 진한 면과 밝은 행동 |
| GRAPHITE·NAVY_DARK·MIST | sunken / text | primary / onPrimary | 어두운 바탕 안에서 실제로 더 낮은 면 사용 |

어두운 팔레트의 inverse는 밝아지는 역할이므로 진한 카드에는 쓰지 않는다. 본문과 행동 대비는 `.qa-r7/verification.json`에 실측한다. 진한 카드 안 보조 문구도 기본 글자색을 사용해 투명도 때문에 대비가 떨어지지 않게 한다. 지도 경로색을 카드 장식에 재사용하지 않는다.

원본 역할 값으로 계산한 대비(본문 면/글자, 행동 면/글자): STANDARD 17.03:1 / 7.82:1, NAVY_LIGHT 17.03:1 / 7.82:1, HIGH_CONTRAST 18.89:1 / 10.65:1, GRAPHITE 14.23:1 / 7.28:1, NAVY_DARK 14.19:1 / 7.26:1, MIST 12.06:1 / 6.79:1. 6팔레트 전체 프레임 및 명시적 어두운 게시 페이지에서도 본문 대비 실패가 없었다.

## 4. 구성 요소와 정렬 계약

### 목록 행 — 가장 중요한 계약

후행 상태가 있는 행은 **40dp 선행 → 8dp 간격 → 가변 본문 → 8dp 간격 → 72dp 후행 → 8dp 간격 → 24dp 쉐브론**이다. 폭 364dp 카드 안쪽은 332dp, 가변 본문은 172dp이다. 상태 없는 행은 40dp 선행 → 12dp → 가변 본문 → 12dp → 24dp 쉐브론을 사용한다. 후행 폭은 같은 목록 안에서 절대 섞지 않는다. 큰 글자에서 제목과 상태가 충돌하면 상태를 다음 줄의 같은 고정 격자로 옮긴다.

제목 16/24, 보조 줄 14/20. 행은 최소 80dp, 상하 패딩 16. 본문은 `weight(1f)`, 선행·후행·쉐브론은 고정 폭. 후행은 알약 없이 `● 연결됨` 형태이며 오른쪽 정렬한다. 상태 영역 높이 24dp를 제목 첫 줄의 중앙에 맞춘다. 행의 보조 줄 길이는 후행의 y 위치에 영향을 주지 않는다. 쉐브론도 제목 첫 줄 중앙. 같은 목록에서 후행 오른쪽 x 편차와 제목 대비 y 편차는 1px 이내다. 서로 다른 행의 절대 y 좌표가 같다는 뜻은 아니다.

상태가 없는 목록은 후행 열을 목록 전체에서 생략할 수 있다. 경고의 ‘숨기기’, 전송의 ‘다시 보내기’처럼 독립 행동이 있으면 후행 열을 88 × 56dp 버튼으로 두고, 해당 목록의 모든 행에서 같은 폭을 사용한다. 버튼 문구는 13/20, 좌우 패딩 8dp이며 제목 첫 줄 중앙에 맞춘다. 장치 사진이 들어가는 압축 행은 40dp 이미지 슬롯을 사용한다.

### 카드 머리

제목 첫 줄 28dp와 상태 배지 24dp를 같은 grid row의 중앙에 놓는다. 사진은 별도 72 × 64dp 슬롯. 상태는 카드당 1개, 배지 폭은 해당 종류에 고정(기본 64dp), 아이콘 없이 점과 짧은 문구. 메타 줄은 제목 아래 4dp이며 배지 중앙을 이동시키지 않는다.

### 필터

높이 48dp, 좌우 패딩 12, gap 8, 첫 필터 왼쪽은 콘텐츠 시작선. 체크 아이콘 없이 선택 면·글자색만 바꾼다. 선택 전후 font-weight도 동일해 폭 변화가 없다. 넘치면 필터 컨테이너 안에서만 가로 스크롤하며 줄바꿈하지 않는다.

### 4단계 영수증

종료–저장–수신–보고를 `repeat(4, 1fr)` 한 줄 격자로 표시한다. 각 셀 위쪽 12dp 점, 점 사이 1dp 선, 아래 13/20 짧은 단계 이름, 그 아래 상태를 둔다. 현재까지 확인된 단계만 success 점, 미확인은 빈 점과 pending 문구, 보고 전은 빈 점과 neutral 문구. 완료로 추정하지 않는다. 상세 근거는 격자 아래 2열 속성 목록에 모두 보존한다. 최근 수집의 축약형도 같은 4열이며 줄바꿈하는 칩을 사용하지 않는다.

### 지표·버튼·지도

- 4지표: 4등분, gap 8, 타일 높이 80dp, 패딩 8, 라벨 20dp, 숫자 36dp 기준선 동일. 정상 수치의 장식색 없음.
- 주 버튼: 56dp, 반경 12, 하단 영역 전체 폭. 보조 48 이상. 두 버튼이면 `weight(1f)` 각각 동일 폭, gap8. 필터를 제외한 행동은 알약이 아니다.
- 진한 작업 카드: 패딩 20, 사진 카드와 20~24dp 간격, 제목 22, 시계 40. 배정 대기와 수집 중을 동일 틀에 표현.
- 지도 카드: 반경 16, 준비/결과 200dp, 진행 240dp, 전체화면 가변. 조작 버튼 48, 간격 8, 불투명 mapPlate. 경로는 흰 casing과 실선·대시를 함께 쓴다. 지도 위 작은 상태표시는 점·문구이며 조작 영역이 아니다.
- 알림: 장식 아이콘 40 + 본문 가변 + 삭제 48. 심각도는 실제 상태의 작은 아이콘/문구에만 사용한다.

가이드 페이지 ‘정렬 규칙’ 패널에 12dp 점선 격자를 깔고, 같은 364dp 예시 폭에서 R6의 가변 폭 알약·선택 체크로 인한 폭 이동·영수증 줄바꿈과 R7의 고정 열·일정 필터·4등분을 나란히 보여 준다. R6 예는 정렬 문제만 재현하며 반려된 추가 색은 재도입하지 않는다.

## 5. 로고와 로딩

기존 구현을 읽고 설계했다: `GeonLoader.kt`는 회색 베이스, 두 물결, shine이 2400ms 주기로 움직인다. `StartupScenes.kt`는 88dp 로더, GEO-X 제목, 실패 원인·재시도를 제공한다. `GeoBrand.kt`는 원본 crop과 어두운 면의 워드마크 단색 처리를 허용한다.

### 자산과 사용 규칙

- `geo_symbol.png` 340 × 340 원본을 그대로 사용. 단독 표시는 최소 24dp, 작은 인라인 로더 40dp, 시작 128dp, 실패 72dp.
- `geo_logo.png`는 1000 × 338 비율. 심볼 x0–290, 워드마크 x310–1000 / y0–260. 워드마크 단독 사용 시 이 690 × 260 영역만 무손실로 잘라 `geo_wordmark.png`로 저장하며, 최소 폭은 88dp(높이 약 33.16dp)다. 원본 비율·색을 유지하고 영문 태그라인은 포함하지 않는다. 태그라인을 포함한 전체 로고는 최소 200dp.
- 외곽 여백은 심볼 폭의 1/4(128dp이면 32dp), 전체 로고는 심볼 높이의 1/4 이상. 앱 아이콘은 `geo_app_mark.png` 원본 사용.
- 색 변경·회전·늘림·일부 재그림·자체 그림자·다른 도형에 끼워 넣기 금지. `GeoBrand.kt`처럼 어두운 팔레트의 어두운 면에서는 워드마크에만 text 단색 tint를 적용하며 심볼에는 적용하지 않는다. HTML은 원본 crop의 alpha 마스크와 팔레트 text를 사용한다. GRAPHITE·NAVY_DARK·MIST에 적용하고 밝은 팔레트는 원본 색이다.

### 한 가지 동작: 심볼을 따라 올라오는 리빌

원본 심볼을 alpha0.16으로 한 번 놓고, 원본 그대로의 두 번째 이미지를 아래에서 위로 드러낸다. 로켓·줄무늬의 실루엣이 계속 보이고 상단 로켓이 마지막에 나타난다. 물결·궤도·shine·바운스를 추가하지 않는다. 주기 2400ms: 0–1680ms 선형 상향 리빌, 1680–2160ms 완성 유지, 2160–2400ms 전경 alpha1→0으로 초기화. 실제 진행률이 아니므로 %나 단계 완료를 만들지 않는다.

Compose Canvas 구현: 원본 ImageBitmap을 aspect-fit, alpha0.16으로 그린다. `rememberInfiniteTransition`의 t=0..1을 사용한다. `reveal=min(t/0.7,1)`, `foregroundAlpha=1`(t≤0.9), 이후 `(1-t)/0.1`. 같은 dstRect 위 `clipRect(top=h*(1-reveal)) { drawImage(bitmap, alpha=foregroundAlpha) }`. 이미지의 색·크기·좌표는 고정한다. 재구성마다 비트맵을 디코딩하지 않는다. reduced motion은 transition을 생성하지 않고 alpha1의 완성 원본을 한 번 그린다.

- **L1 시작**: surface 전체 면, 중앙 128dp 심볼, 32dp 간격의 GEO-X 32/40, 12dp 뒤 ‘장치 정보를 불러오는 중입니다.’ 16/24. 하단에는 태그라인 없는 워드마크만 폭 88dp, 원본 690:260 비율로 표시한다. 워드마크 영역의 하단은 시스템 탐색 영역 위 32dp다. 밝은 팔레트는 원본 색, 어두운 팔레트는 워드마크만 text 단색을 쓴다. 불필요한 지연은 추가하지 않고 기존 StartupTiming을 상속.
- **L2 화면 안**: 기존 상단바·탭은 유지. 장치 사진·4지표·목록 자리에 움직이지 않는 sunken/field skeleton, 상단 40dp 심볼과 실제 불러오기 문구. skeleton shimmer는 쓰지 않는다.
- **L3 실패**: alpha0.28의 원본 72dp 심볼, 제목 ‘장치 정보를 불러오지 못했습니다’ 22/32를 균형 있는 두 줄로 표시한다. `AppRestoreViewModel.kt`의 `restoreFailureWords` 원문 ‘저장된 장치 정보를 읽지 못했습니다. 다시 시도해 주세요.’를 한 줄 13/24, 자간 −0.25dp로 표시하고 56dp 전체 폭 ‘다시 시도’를 둔다. 중복 실패 상자나 저장 자료 보존 주장은 넣지 않는다.

HTML에서 실제 CSS `@keyframes` 예시를 제공한다. `prefers-reduced-motion: reduce`이면 animation:none, foreground clip 해제, opacity1. 실패의 흐림은 불투명도만 적용한다. TalkBack live region은 ‘장치 정보를 불러오는 중입니다’ 한 번, 프레임마다 낭독하지 않는다. 실패 시 원인과 재시도 순서로 초점을 제공한다.

## 6. R6 대비 변경

1. 새 타일색·work색을 제거하고 colors.json 원본 6팔레트로 복원했다.
2. 목록 상태는 알약에서 고정 폭 점·문구로, 카드 머리는 고정 24dp 배지로 바꿨다.
3. 필터 선택에서 체크를 제거해 선택 전후 폭을 고정하고, 영수증은 한 줄 4열로 재편했다.
4. 사진·큰 숫자·진한 카드·지도·영상·썸네일은 유지하고 중립 면과 24dp 섹션 리듬으로 변화를 만들었다.
5. 원본 심볼 리빌 로딩과 skeleton·실패 화면, 실제 CSS 애니메이션과 reduced motion 규칙을 추가했다.
6. 감독 검토를 반영해 L1 하단을 원본 워드마크로 교체하고 L3을 앱의 실제 실패 문구로 정리했다. 게시 페이지의 읽기용 영문 표시는 한국어로 바꿨다.
