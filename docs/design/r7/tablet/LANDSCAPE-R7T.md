# R7T 패드 가로 보강

기준: SM-T547U · 1920×1200px · 240dpi · **1280×800dp · 글꼴 1.1**. 기존 [패드 규칙](STYLE-R7T.md), [패드 시안](index.html), [공통 부품](../COMPONENTS-R7.md), [스타일 가이드](../../STYLE_GUIDE.md)를 따른다.

## 적용 조건과 공통 치수

- 방향 센서 대신 safeDrawing을 제외한 현재 창의 dp를 쓴다. 기존 EXPANDED(폭 ≥840dp) 및 두 칸 최소 폭 조건에 **폭 > 높이, 안전 높이 480~840dp**를 더한다. 600dp 이하만 허용하면 전시 패드의 800dp 높이가 제외되므로 상한을 840dp로 정한다. 높이 <480dp·배율 ≥1.5·최소 폭 미달은 기존 스크롤 배치다. 폰·패드 세로는 기존 배치다.
- `s=max(1,fontScale)`, `P=창 폭−레일(80dp 또는 0dp)`. 최소 `P≥320s+400s+24+48`을 유지한다. 배율 1.1/레일 사용 시 전체 최소 폭은 944dp다. IME·분할 창·회전 시 재계산한다.
- 레일80, 외곽24, 열 사이24, 위24, 스크롤 끝32dp. 전체 최대1560dp. 목록400/작업 왼쪽520dp를 유지한다. 1280dp에서는 장치·전송·설정 **400/728dp**, 작업 **520/608dp**다.
- 가로 상세의 720dp 제한을 해제해 상세 카드와 상단의 끝선을 맞춘다. 내부 지표·행은 실제 가용 폭으로 기존 격자 규칙을 적용한다. 가로 버튼은 기존560dp 상한을 해제해 소속 카드·열 너비를 채운다. 이 두 항목은 STYLE-R7T의 읽기 폭 규칙에 대한 예외다. 728dp 상세의 미세한 중앙 여백과 버튼만 짧아지는 문제를 해소한다.
- 색·글자 크기·카드 모양·최소 터치 크기는 R7 그대로다. 기존 6팔레트·fixed 토큰만 재사용한다.
- 두 칸 목록의 선택 줄은 `primaryTint`를 카드 가장자리까지 채우고, 안쪽 여백은 칠해진 면 안에 둔다. 첫·마지막 줄은 카드 반경에 맞추고 선택 줄에 닿는 구분선은 숨긴다.
- 근거: 2026-10-26 사용자 의견 — 선택색은 유지하되 카드 안쪽에 어정쩡하게 남는 흰 띠와 각진 바탕을 없앤다.

## 화면별 결정

| 화면 | 지금 → 바뀐 배치 | 치수·행동 |
|---|---|---|
| 카메라 | 최대720dp 중앙 세로 열 → 전체 폭의 영상 + 오른쪽 조작 열 | 레일 없는 집중 화면. 기존 뒤로 헤더 아래, 외곽 가로24/세로12, 조작200, 간격24dp. 영상은 나머지 영역에서 원본 비율을 보존하는 최대 Fit. 높이를 모두 쓸 수 있으면 높이 기준, 폭이 먼저 차면 폭 기준으로 축소한다. 자르거나 늘리지 않는다. 1280×800 영상 기준 창 폭1280에서 약1008×630dp까지 표시 가능하며 실제 inset·헤더 높이에 따라 달라진다. |
| 카메라 상태·조작 | 영상 위·아래 상태와 큰 빈 영역 → 오른쪽 세로 열 | 장치·실시간/지연·마지막 수신·해상도·캡처·저장 위치. 열은 독립 스크롤. 가로에서는 영상 위의 ‘카메라 영상’ 장식을 없앤다. 캡처 가능 조건·지연 경고·재시도·저장 확인은 기존 계약 유지. |
| 작업 | 오늘 구간 중복, 아래 빠른 기능 잘림 → 왼쪽 장치·오늘 구간/주요 행동·빠른 기능, 오른쪽 최근 수집·다른 구간·장치 작업 | 정상 연결/배율1.1의 핵심 네 묶음을 첫 화면에 배치한다. 최근 수집은 최대2개 미리보기, 나머지는 ‘전체 기록’. 왼쪽 카드로 실제 제시한 구간만 오른쪽에서 제외한다. 주요 행동이 복구·수집 진행·보고라면 구간 목록은 유지한다. ‘구간 직접 고르기’는 오른쪽 카드와 같은608dp 폭. 긴 이름·경고·배율1.3에서는 글자와 버튼을 줄이지 않고 열을 스크롤한다. |
| 장치 | 목록/상세 제목 ‘장치’ 반복 + 상세 세로 나열 → 목록 ‘장치’ / 상세 ‘장치 상태’, 사진·지표 아래 두 열 | 상세 폭728dp일 때 내부352/352, 간격24dp. 왼쪽 센서·상태, 오른쪽 연결·데이터·관리·등록 해제. 최소 `560s+24dp` 미달이면 내부 한 열. 위험 동작은 오른쪽 끝의 기존 확인 흐름 유지. |
| 전송 | 오른쪽 무선택 상태가 영구 로딩처럼 보임 → 빈 상태에서 선택 안내 | 기존 첫 항목 선택 우선순위 유지. 로딩·오류와 구분해 ‘전송 내역을 선택하세요’ 및 왼쪽 목록/파일 보내기 안내. 실제 기록이 있으면 영수증 상세. 수신·보고 증거 판정은 그대로다. |
| 설정 | 오른쪽 뒤로 + 왼쪽과 어긋나는 상단 높이 → 상세 제목과64dp 상단 | ‘화면 테마’ 등 구체적 상세 제목 유지. 선택 즉시 적용과6팔레트 계약 유지. |
| 두 칸 공통 | 상세 뒤로 화살표 → 해당 상세 루트에서 숨김 | 상세 루트 문맥은 두 칸 가로에서만 제공한다. 단일 열로 돌아가면 원래 뒤로 화살표를 표시한다. 카메라 등 집중 화면의 뒤로는 유지한다. |

## 검증과 인계

- 순수 함수: `geoLandscapeLayout`, `geoDeviceDetailColumns`. JVM의 `LandscapeLayoutPolicyTest`에 전시 크기·배율1.1/1.3/1.5/2.0·480/600/840dp 높이·944dp 최소 폭·내부 열 경계를 추가한다.
- Compose: `R7LandscapeLayoutTest`에서 실제 홈의 핵심 표시·오늘 구간 중복 제거·버튼 폭, 실제 카메라 이미지/조작 분리와 회전 복귀, 상세 뒤로 숨김/복귀·전송 빈 상태를 검사한다. 기존 `R7TabletLayoutTest`는 가로의 ‘다른 수집 구간’ 제목에 맞춘다.
- 작업자는 소스·호출부·타입·경로를 정적으로 확인한다. Gradle JVM/빌드/린트·androidTest 실행과 SM-T547U 가로 캡처는 감독이 수행한다.
- 패드 필수 확인: 1.1배율 첫 화면의 준비하기/빠른 기능/최근 수집, 카메라 영상 확대·지연 시 캡처 비활성·저장 위치, 장치 상세 두 열, 전송 0건/선택·장치 전환, 설정 선택과 회전 후 뒤로, 1.3/1.5배율 및 분할 창 복귀.
