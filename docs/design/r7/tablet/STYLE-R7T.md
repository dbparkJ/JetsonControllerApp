# GEO-X R7T · 패드 전용 디자인

작성: 2026-10-26 · 기준: 승인된 R7 · 단계: 디자인 / 앱 구현 전

## 1. 기준과 범위

- 대상: Galaxy Tab S6 Lite SM-P610, 1200 × 2000px, density 240(1dp = 1.5px). 설계 창은 세로 **800 × 1333dp**, 가로 **1333 × 800dp**다. 1333dp는 2000px/1.5를 반올림한 값이다.
- 시안은 글꼴 배율 **1.0**으로 그린다. 실제 사용자 설정 0.8을 디자인 기준 글자 크기에 미리 곱하지 않는다.
- 색은 저장소 `docs/design/colors.json`의 STANDARD, NAVY_LIGHT, HIGH_CONTRAST, GRAPHITE, NAVY_DARK, MIST와 fixed만 사용한다. 값과 의미는 R7 그대로다.
- R7 원본 장치 사진·심볼·워드마크와 지도·영상 예시, 중앙로 동측·서측 등의 자료를 재사용한다. HTML 글꼴은 Noto Sans KR, 앱은 기존 Pretendard다.
- 앱 저장소는 읽기만 했다. 이번 산출물은 정적인 디자인 검토 페이지이며 수집·전송·설정 변경을 실행하지 않는다.

## 2. 먼저 확인한 기존 구현

`ui/components/geo/shell/GeoWindow.kt`의 실제 규칙:

1. 폭은 가로 safeDrawing을 제외하고, 탐색 chrome을 빼기 전에 측정한다.
2. COMPACT <600dp, MEDIUM 600–839dp, EXPANDED ≥840dp.
3. 레일은 탐색이 보이고 폭 ≥600dp일 때 80dp. `paneWidthDp = widthDp − 80dp`다.
4. 현재 2-pane 조건은 EXPANDED, 높이 ≥480dp, 글꼴 배율 <1.5이며, `paneWidthDp ≥ 320×s + 1 + 400×s + 2×24`다. `s=max(1,fontScale)`.
5. 현재 `GeoPaneLayout`은 1dp 간격과 4:5 가중치를 쓴다. 단일 pane은 바깥 열 최대 720dp, 그 안에 좌우 24dp 패딩이다.
6. `GeoAppShell`은 `twoPane && paneLayout`일 때만 720dp 제한을 해제한다. `JetsonApp.kt`의 현재 허용 경로는 WORK_BROWSE, TASKS, TICKET_DETAIL뿐이다.
7. `GeoRail`은 기존 4탭을 재사용하지만 알림 배지 입력은 아직 없다. `GeoActionArea`는 화면 전체 chrome 측정값으로 고정 여부를 계산한다.

**R3의 단일 pane 최대 720dp를 유지한다.** 카드의 2열 배치는 단일 pane 내부 격자다. 요청한 장치·전송·파일·설정의 가로 목록/상세는 R7T에서 추가하는 명시적 확장이다. 구현 시 허용 경로와 pane 폭 계산을 함께 변경해야 한다. 전역의 모든 화면을 넓히지 않는다.

## 3. 창 크기와 기준점

| 구간 | 탐색 | 본문 / 전환 |
|---|---|---|
| <600dp | R7 하단 탐색 | 폰 R7 유지 |
| 600–839dp | 80dp 레일 | 최대 720dp 한 열. 목록 → 상세 화면으로 전환 |
| ≥840dp, 2-pane 최소 폭 미충족 | 80dp 레일 | 최대 720dp 한 열. 목록 → 상세 전환 |
| ≥840dp, 최소 폭 충족, 높이 ≥480dp, 배율 <1.5 | 80dp 레일 | 지정한 화면만 2-pane |
| 높이 <480dp 또는 배율 ≥1.5 | 폭 ≥600dp면 레일 | 한 열 + 세로 스크롤. 하단 행동은 본문 끝으로 이동 가능 |

### R7T의 2-pane 조건

바깥 여백 24dp × 2, pane 사이 24dp를 적용한다. 기존 1dp 분할 간격을 24dp 공간으로 바꾸므로 다음 식을 사용한다.

```text
s = max(1, fontScale)
W = 가로 safeDrawing을 제외한 창 폭
P = W − (탐색 레일이 있으면 80, 없으면 0)
twoPane = W ≥840 && 안전 높이 ≥480 && fontScale <1.5
          && P ≥ 320s + 24 + 400s + 48
```

- 1.0의 최소 전체 폭은 **872dp**, 1.3은 **1088dp**다. 840dp라는 등급만으로 2-pane을 켜지 않는다.
- Tab 세로 800dp: P=720, 본문 실폭 672dp → 한 열.
- Tab 가로 1333dp: P=1253, 여백 제외 1205, pane 공간 합 1181dp → 2-pane.
- 가로 1280dp: P=1200, pane 공간 합 1128dp → 같은 구조 유지.
- 1280dp는 새 탐색 등급이 아니다. 목록 폭을 안정화하고 남는 폭은 상세·지도에 준다.
- 화면 회전·분할 창에서는 기기 방향 대신 현재 창의 dp를 기준으로 재계산한다.

목록/상세의 실제 폭은 다음처럼 계산한다. 최소 폭 검사에 통과한 뒤에만 적용하므로 음수 폭이나 최소 폭 미만의 상세가 나오지 않는다.

```text
A = P − 48 − 24                     // 외곽 여백과 pane 간격 제외
L = min(max(320s, 400), 440s, A − 400s)
D = A − L
작업 홈 L = min(max(320s, 520), A − 400s)
수집 중 L = min(max(320s, 360), 440s, A − 400s)
```

### 자료 일관성

- 장치 가로는 R7 09의 카메라·GNSS 미연결 장면을 사용한다. 오른쪽 센서도 미연결로 맞춘다. 다른 시점인 R7 10의 연결됨 상태를 동시에 표시하지 않는다.
- 전송 중인 중앙로 서측과 선택한 중앙로 동측 영수증은 별개 항목이다. 수신 확인 그룹의 중앙로 동측을 위에 고정해 선택 강조와 09:20 검증 증거가 함께 보이게 한다. 이 장면에서 같은 중앙로 동측을 보낼 수집으로 중복 표시하지 않는다. 보낼 수집에는 기존 파일 보내기 진입 버튼을 둔다.
- 전송률 100%를 수신 확인으로 바꾸지 않는다. 종료·저장·수신·보고는 기존 증거가 있을 때만 완료 점을 채운다.

### 카드 격자는 창 폭이 아닌 실제 카드 폭으로 결정

| 실제 콘텐츠 폭 / 글꼴 | 지표 격자 | 빠른 기능 | 테마 미리보기 |
|---|---:|---:|---:|
| ≥312dp, 1.0 이하 | 4열 | 가용 폭 ≥400dp면 5열 | 가용 폭 ≥560dp면 3열 |
| 200–311dp | 2열 | 폭 <400dp면 2열 | 320–559dp면 2열 |
| <200dp | 1열 | 최소 항목 폭 미충족이면1열 | <320dp면1열 |
| 1.3 | 원칙 2열 | 2열 | 2열 |
| ≥1.5 / ≥2.0 | R7: 2열 / 1열 | R7: 2열 / 1열 | 측정 결과에 따라2열 / 1열 |

800dp 세로 작업 홈의 사진 카드 실폭은 324−32=292dp이므로 네 지표는 **2 × 2**다. 가로 사진 카드는 실폭488dp이므로 **4열**이다. 지표를 억지로 작게 만들어 4열을 유지하지 않는다. 사진은 원본72 ×64dp, 세로 홈의 작은 사진 카드에서는56 ×56dp 안에 비율 보존한다.

### 하단 행동과 스크롤

- 각 pane은 자신의 세로 스크롤과 하단 행동 영역을 소유한다. 목록과 상세가 독립적으로 움직인다.
- 상세 하단의 버튼은 해당 pane 안에 둔다. 좌우16–24dp, 세로12dp, 버튼 최소56dp. 버튼 폭을 창 전체로 늘리지 않는다.
- 고정 행동은 surface + 상단1dp border를 사용한다. 본문 위에 덮지 않고 Column에서 실제 높이를 차지한다.
- 남는 본문 높이 ≥280dp일 때 고정한다. 높이가 부족하거나 IME가 열리면 본문 끝으로 이동한다. `GeoActionArea`의 계산에는 **자기 pane의 높이와 chrome**을 전달한다.
- 검색 IME가 레일을 숨기는 현재 shell 정책은 유지한다. 키보드 전후 열을 오갈 때 검색어·선택·스크롤을 보존한다.

## 6. 정렬과 글꼴

R7 글자 크기를 그대로 사용한다. 화면24/32·700, 작업22/32·700, 섹션18/28·700, 본문·버튼16/24, 보조14/20, 상태·필터13/20, 지표28/36,시계40/48sp. 숫자는 tabular-nums다. 단위13/20과 숫자 사이2dp.

- 상태 목록: 선행40 → gap8 → 가변 본문 → gap8 → **후행72** → gap8 → 쉐브론24dp. 목록 카드 안쪽16dp. 최소 행 높이80dp.
- 상태 유무는 목록별로 한 번 결정한다. 상태가 비어도72dp를 예약한다. 행 너비가 넓어져도 후행은 같은 끝선에 둔다.
- 기본 상태의 첫 줄 중심은 제목 첫 줄 중심에 맞춘다. 카드 머리 배지는24dp·반경8, 카드당 하나.
- 독립 행동은88 ×56dp 고정 열. 숨기기·다시 보내기·등록·보내기는 상태 열과 섞지 않는다.
- 필터는 최소48dp, 좌우12dp, gap8, 선택 전후 동일 글꼴·폭, 체크 추가 없음. 넘치면 필터만 가로 스크롤한다.
- 이름·원인·근거는 말줄임하지 않는다. 파일명은 원본을 보존하고 `_`·경로 구분 뒤와 긴 단어에서 줄바꿈을 허용한다.
- 4단계 영수증은 종료·저장·수신·보고 **한 줄4열**을 유지한다. 근거는 아래의 별도 속성 목록이다.

### 글꼴 배율 0.8

dp 여백·pane·48dp 터치·56dp 버튼은 그대로다. sp만 시스템 배율로 바뀐다. 작은 글자 때문에 더 많은 열을 만들거나2-pane 기준을 낮추지 않는다. 계산에서 `s=max(1,fontScale)`을 유지한다. 지표4열·빠른 기능5열 조건은1.0과 같다.

### 글꼴 배율 1.3

1. 단일 열은720dp 유지. 세로 홈의 사진·작업 카드와 최근 수집·구간은 각각1열로 바꾼다. 빠른 기능2열, 지표2열이다.
2. 목록 최소416dp, 상세 최소520dp를 만족할 때만2-pane. 1333dp와1280dp 가로는 유지된다. 최소 전체 폭1088dp 미만은 한 열이다.
3. 제목·설명·수신 근거의 줄 수를 제한하지 않는다. 행 높이와 카드 높이를 내용에 맞춰 늘린다.
4. 좁은 목록에서는 후행 상태·88dp 행동을 같은 오른쪽 열의 다음 줄로 내린다. 텍스트를 축소하지 않는다.
5. 카드 머리 배지는 높이를 내용에 맞춰 늘리거나 제목 다음 줄로 내린다. 배지가 제목을 덮지 않게 한다.
6. 버튼은 minHeight만 지정하고 내용이 두 줄이면 높이를 늘린다. 필터는 minHeight48과 가로 스크롤을 유지한다.
7. 레일80dp와 탭64dp는 최소치다. 라벨이 더 높으면 탭도 늘어나고 레일 안에서 세로 스크롤한다.
8. 시계와 주요 행동은 왼쪽 pane의 위·아래 위치를 유지하고, 카메라·관찰 수치는 중간에서 스크롤한다.

## 7. 시작 로딩과 브랜드

- L1은 레일 없는 surface 전체 화면. 시스템 inset을 제외한 본문 정중앙에 기존 심볼128dp → gap32 → GEO-X32/40 → gap12 → 기존 안내16/24sp.
- 워드마크는 제공된 `geo_wordmark.png` 원본 비율 그대로 **88 ×33.16dp**, 시스템 하단 inset 위 **32dp**. 가로에서도 같은 크기다.
- 밝은 팔레트는 원본 색, 어두운 팔레트는 워드마크만 text tint. 심볼·사진은 원본 색을 유지한다.
- 2400ms 리빌과 prefers-reduced-motion 대응은 R7 CSS·GeonLoader 규칙을 재사용한다. 검수 캡처에서는 완성 심볼에 정지시킨다.

## 8. R7 대비 변경점

1. ≥600dp 하단 탭을 기존80dp GeoRail로 전환, 탭에 알림 상태를 전달한다.
2. 세로 작업 홈은 같은720dp 열 안에서 사진/작업과 최근 수집/구간을2열로 배치한다.
3. 가로 작업 홈은 두 열로 정보 묶음을 재배치한다. 수집 중에는 지도 확대와 왼쪽 제어 pane을 도입한다.
4. 장치·전송·파일·설정 경로에 한정해 목록/상세2-pane을 추가한다. 단일 pane720dp 규칙과 기존 상태·행동 계약은 유지한다.
5. 2-pane 사이1dp 간격을24dp로 바꾸고, 목록 폭 상한·상세 읽기 폭 상한을 적용한다.
6. 폰의 화면 전체 고정 행동을 선택된 상세 pane의 하단 행동으로 옮긴다.

새 팔레트·새 부품 모양·새 기능은 추가하지 않는다.
