# 앱 구조 재설계 계획 — 장치 콘솔

2026-10-17 결정. Claude와 astra의 3차 토론으로 확정했고, 화면 시안은 Claude Design 캔버스 "GEO& 장치 관리 앱 리디자인"에 있다. 이전 계획(현장 수집 중심의 홈·수집·파일·설정)은 Git 이력에서 볼 수 있다.

## 제품 명제

폰이 Jetson의 화면이다. 장치 상태는 한눈에, 작업은 한 번에 시작하고, 전송은 영수증으로 끝까지 확인한다. 소유자가 정한 네 업무는 장치 관리, 모니터링, 작업 지시, 서버 통신 모니터링이다.

## 탭과 시작

하단 탭은 **장치 · 작업 · 전송 · 설정** 네 개다. 넓은 화면(840dp 이상)에서는 같은 네 항목을 레일로 보인다. 다섯 번째 "활동"은 GEON Work 연동 때 추가한다([연동 제안](../integrations/GEON_WORK_INTEGRATION_PROPOSAL.md)).

- 시작은 항상 장치 루트다. 등록 장치가 0대면 루트가 첫 실행 카드(QR 등록 우선, 블루투스·장치 직접 연결은 "다른 방법")를 보인다.
- 연결 허브 화면은 장치 루트로 흡수한다. 라우트는 지우지 않는다.
- 탭 루트에는 뒤로 화살표가 없다. 탭을 다시 누르면 그 탭의 루트로 간다.

## 루트 화면

| 탭 | 루트 내용 | 하위 화면 |
|---|---|---|
| 장치 | 현재 장치 카드(사진, 이름, 연결 상태, 마지막 응답, 온도·저장 여유·실행 중 작업, 네이비 띠의 다음 행동 1개) · 다른 장치 행 · 확인할 일 1개 · 앱바의 알림과 장치 추가 | 장치 상세: 상태(온도·저장·CPU/GPU·메모리) · 작업 · 센서(카메라 미리보기, 위치 지도) · 연결과 데이터(연결 방법 시트, 장치 Wi-Fi, 장치 파일) · 장치 관리(재부팅·전원 종료) · 고급 |
| 작업 | 현장 수집 고정 카드(마지막 구간, "점검하고 시작") · 실행 중 · 최근 작업(3칸 영수증) · 다른 작업 | 수집 준비, 수집 진행, 수집 결과 영수증, 작업 상세(상태·메타데이터, 읽기 전용), 작업 기록 |
| 전송 | 진행 중(속도·남은 시간은 계산값만) · 대기 · 실패(원인과 다시 시도) · 서버 수신 확인 · 같은 네트워크 제한 안내 한 줄 | 보낼 파일 고르기(장치 파일 브라우저), 서버 파일, 전송 상세 |
| 설정 | 알림 기준 · 화면 테마 · 서버 연결 · 도움말 · 앱 정보 · (개발자 모드일 때만) 고급 | 서버 연결 프로필(보기는 모두, 추가·편집은 개발자 모드), 고급 도구 |

3칸 영수증은 한 번의 수집을 "수집 종료 → 장치 저장 → 서버 수신"으로 보여 준다. 서버 수신은 실행 ID가 정확히 일치할 때만 확인으로 표시하고, 모르면 대기나 미확인으로 둔다.

## 숨김과 동결 (삭제 없음)

- 고급(개발자 모드, 앱 정보 7회): 작업 등록·편집·정책 편집·작업 로그, 팬 수동 제어, 연결 진단 기록, 카메라·GPS 테스트, Jetson 경유 서버 조회, 업로드 서버 대상, 서버 휴지통 비우기, 개발자 도구.
- 장치 관리(모든 사용자): 재부팅, 전원 종료. 장치 설치 시 전원 기능이 켜져 있고, 연결되어 있고, 다른 조작과 수집이 진행 중이 아닐 때만 활성화한다. 확인 대화상자에 장치 이름을 넣는다.
- 개발자 모드 토글은 기본 설정 화면에 없다. 켜진 뒤에만 고급 행이 보인다.

## 동작 규칙

1. **자동 이동 0**: 배경 상태 변화(등록 필요, 수집 종료, 연결 성공)로 화면을 바꾸지 않는다. 사용자가 시작한 흐름의 완료(페어링 성공 → 장치 루트)만 허용한다. 수집이 끝나면 진행 화면이 그 자리에서 "결과 보기"를 보인다. 개발자 모드를 끄면 고급 화면에서 나가는 것은 권한 경계라 유지한다.
2. **뒤로 가기**: 연결 허브로 돌아가던 pop은 모두 장치 루트로 돌아간다.
3. **연결 안내**: 앱바 아래 인라인 배너 하나. 콘텐츠를 밀어내고 제목을 가리지 않는다. 배너 종류는 주의와 오류 두 개다.
4. **마지막 상태 저장**: 장치별 마지막 응답 시각, 온도, 저장 여유, CPU/GPU, 실행 중 작업, 전송 상태를 휴대폰에 저장해 오프라인에서도 보인다.
5. **연결 판정 하나**: 화면마다 따로 계산하던 연결 단계를 `deviceConnectionUi` 하나로 판정한다. 서버 업로드 시작은 같은 네트워크(LAN)에서만 된다는 정책은 그대로 두고 이유를 한 줄로 보인다.
6. **권한**: 등록 장치가 1대 이상이면 실행 시 권한을 요청한다. 0대면 첫 실행 카드에서 요청한다.
7. **위험 조작 확인**: 장치 Wi-Fi 변경은 장치 이름, 새 네트워크 이름, "적용하면 지금 연결이 끊길 수 있습니다"를 담은 확인 뒤에 보낸다. 재부팅·전원 종료도 같다.
8. **서버 프로필**: 기본 환경을 미리 고르지 않는다. 저장과 연결을 분리한다.
9. **알림**: 알림마다 장치 이름을 넣고 온도는 °C로 쓴다. 벨 숫자는 24시간 안의 읽지 않은 알림만 센다. 알림 화면을 열면 읽음 처리한다.
10. **오류 문구**: 원시 예외 문구 대신 `userFacingFailure`로 원인과 할 수 있는 일을 보인다. 원시 정보는 개발자 모드에서만.

## 시각 규칙

색과 문구는 회사 앱 GEON Work와 맞춘다. 역할 이름(`LocalGeoColors`)은 유지하고 값만 바꾼다.

| 역할 | 값 |
|---|---|
| 바탕 | #F3F5F8 |
| 표면 | #FFFFFF, 낮은 표면 #F8F9FB |
| 글자 | #171B26 · 보조 #3B4252 · 약한 글자 #5E6676 |
| 선 | 장식 #E2E6EC · 입력·조작 경계 #838A99 |
| 주요 행동 | #2550A3 |
| 브랜드 네이비 | #1A2147 (장치 카드의 다음 행동 띠에만) |
| 상태 | 확인 #0F6B4F · 주의 #8A5A00 · 실패 #B42318 · 안내 #1F6FA8 · 미확인 #5E6676, 각 부드러운 바탕 |

- 글꼴: Pretendard 가변 글꼴(`res/font/pretendard_variable.ttf`, OFL). 굵기는 variation 설정으로 명시한다. 크기와 줄높이는 기존 `Type.kt` 값을 유지한다. 숫자는 tabular.
- 반경: 표면 12dp, 컨트롤 8dp, 알약 모양은 상태 칩에만.
- 버튼은 한 모양(8dp, 주요 버튼 높이 52dp). 화면당 채워진 주요 버튼은 하나.
- 그림자는 시트·메뉴에만. 카드에는 1dp 테두리 대신 바탕과 표면의 명도 차를 쓴다. 목록 안 구분선은 허용한다.
- 아이브로(제목 위 작은 라벨), 단계 번호 장식, 같은 모양 타일을 줄지어 놓는 배치를 쓰지 않는다. 선택은 밑줄 탭으로 보인다.
- 상태 어휘: 연결됨 · 연결 가능 · 오프라인(마지막 응답 시각) · 응답 없음 · 확인 중. "장비"는 쓰지 않고 "장치"로 쓴다. "확인 필요" 단독 문구와 UUID 노출을 쓰지 않는다.
- 문구: 존댓말, 상태는 "~습니다", 안내는 "~세요", 버튼은 명사형, 느낌표·이모지 없음.

## 로딩

- 시스템 스플래시: 밝은 바탕(#F3F5F8, 다크 #11141A)에 공식 GEO& 심볼만.
- 인앱 로딩: 장치 목록 복원이 300ms를 넘을 때만 심볼(`geo_symbol`), "GEO& 도로관리장치", "장치 정보를 불러오는 중입니다."를 보인다. GEON Work 로딩 화면과 같은 구성이다. 1.6초 고정 환영 화면과 30분 뒤 재노출은 없앤다.
