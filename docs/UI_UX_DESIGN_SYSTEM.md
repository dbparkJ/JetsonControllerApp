# UI 구현 계약

화면 구조와 탭은 [앱 구조 재설계 계획](design/APP_REBUILD_PLAN.md), 색·글꼴·컴포넌트 규칙은 [스타일 가이드](design/STYLE_GUIDE.md)와 [colors.json](design/colors.json)이 기준이다. 이 문서는 화면을 바꿀 때도 지켜야 하는, 실제 코드와 API에 맞춘 동작 계약만 적는다. 제품 구현은 Kotlin / Jetpack Compose이고 PNG·HTML을 화면으로 붙이지 않는다.

## 실제 코드에 맞춘 동작

| 관찰 | 채택한 표현/동작 | 사용자 영향 |
|---|---|---|
| 업로드는 rootId/path/targetId 단일 원본 경로 | 보낼 파일 고르기는 폴더 한 개 단위, 파일 임의 묶음 없음 | 선택한 폴더 전체만 전송 |
| 서버 사전 접근 확인 API 없음 | 접근·인증은 전송 시 확인한다고 안내 | 같은 네트워크 연결을 서버 인증 성공으로 오인하지 않음 |
| 서버 업로드 시작은 같은 네트워크(LAN)에서만 가능 | `TransportPolicy`와 Repository 정책 유지, 전송 탭에 이유 한 줄 | 장치 직접 연결·블루투스 상태에서 제한 이유가 보임 |
| 모바일 RTK는 RTCM 중계 | 파일 업로드·위치 정밀도와 별도 표시 | RTCM 바이트를 파일 전송량으로 보이지 않음 |
| 작업 상태 폴링 5초 | 세 번의 폴링 간격(15초)을 넘으면 현재 상태 미확인 | 끊김 뒤 작업 없음·실행 중으로 단정하지 않음 |
| 제어 응답은 접수와 실제 실행을 구분해야 함 | 처리 중 문구 유지, 다음 상태 조회로 조정 | 중복 클릭·새로고침 재명령 방지 |
| 카메라 센서 active만으로 실제 프레임을 보장하지 않음 | 받은 프레임·오류·4초 최신성 검사, 미수신이면 실시간 표시 금지 | 마지막 영상과 현재 수신을 구분 |
| 정밀 위치 미확인은 전원 꺼짐을 뜻하지 않음 | 정밀 위치·대략 위치·위치 없음·미확인으로 구분 | 전원·보정·측위 품질 혼동 방지 |
| API가 작업 경과 시간·저장 파일 수를 보장하지 않음 | 제공되지 않은 값은 만들지 않고 실제 확인 시각을 표시 | 가짜 진행률·남은 시간·정상값 없음 |
| 전송 속도·남은 시간 | 휴대폰이 3초 이상 진행을 관측했을 때만 계산값을 보이고, 그 전에는 장치가 보낸 값, 둘 다 없으면 생략 | 근거 없는 남은 시간 없음 |
| 서버 수신 확인 | 실행 ID가 정확히 일치하는 전송에만 확인 표시, 그 밖에는 대기·미확인 | 수신 미확인을 실패로 단정하지 않음 |

위 최신성 임계값은 기존 폴링 주기에 근거한 UI 정책이며 실제 장치 성능 측정값이 아니다. 위험 확인창은 대상 장치와 중단 영향을 표시하고, 취소하면 명령을 보내지 않는다.

## 연결 안내

연결이 필요한 화면에서 연결이 없으면 앱바 위에 인라인 배너 하나를 보인다. 배너는 콘텐츠를 밀어내고 제목을 가리지 않으며, 상태 표시줄 inset은 한 번만 적용한다. 종류는 주의와 오류 두 가지다. 연결 상태 문구는 `deviceConnectionUi`(연결됨 · 연결 가능 · 오프라인 · 응답 없음 · 확인 중) 하나로 만든다.

## 디버그 디자인 검수

`src/debug/.../CobaltGalleryActivity.kt`는 Repository가 없는 Compose 시안 갤러리다. `DEBUG 시안 · 장치 통신 없음`을 표시하며 release 소스 세트에 없다. 화면 인자: home, tasks, detail, data, settings, offline, welcome, 그리고 dark / fontScale. `src/androidTest/.../CobaltFieldScreenTest.kt`의 캡처는 실제 Compose 렌더링이지만 그 안의 상태·장치명·수치는 테스트 fixture이므로 실제 Jetson 관측값과 구분한다.
