00_START_HERE.md와 JETSONCONTROLLER_COBALT_FIELD_V5.md를 읽고,
이 폴더의 COBALT_FIELD_STYLE_GUIDE.md, design/tokens.json,
screens/의 화면 시안을 기준으로 dbparkJ/JetsonControllerApp을 리빌딩해.

이번 기준은 마지막에 보여준 Cobalt Field V5야.
네이비·코발트 블루·아이스 블루·오프화이트를 사용하고,
V4의 초록·청록·포리스트·라임 팔레트로 되돌리지 마.
이전 생성형 홍보 이미지는 구현 기준이 아니야.
홈·작업·데이터·설정 4탭과 작업 중심 UX, 기존 안전·복원 계약은 유지해.

먼저 이 지시 MD의 실제 경로, AGENTS.md, 현재 브랜치·HEAD·미커밋 변경,
기존 연결 안정성 코드를 확인하고 사용자 작업을 보존해.
이미 리빌딩된 부분은 재작성하지 말고 필요한 차이만 반영하며,
아직 구형 UI인 부분은 문서의 새 구조로 구현해.

문서는 기본안이지 실제 장치보다 우선하는 절대 명세가 아니야.
스마트폰·Jetson·API를 확인해 맞지 않는 부분은 스스로 근거를 검토해 조정하고,
무엇을 왜 바꿨는지 결과 보고서에 남겨.
실제 전송 단위, 연결 방식별 capability, RTK 중계와 파일 업로드의 차이,
요청 접수와 실행 확인, 센서·영상의 최신성을 사실대로 표현해.

PNG를 화면에 붙이거나 HTML을 제품 WebView로 넣지 말고
실제 Compose UI로 구현한 뒤 기존 Repository와 기능을 재연결해.
시안 수치와 정상 상태는 Preview/debug에서만 사용해.
기존 등록·인증·측정 파일·초안·네트워크 안정성·안전장치를 훼손하지 마.

Figma를 활용할 수 있으면 실제 파일 상태를 읽고 사용해.
접근이 막히면 figma-plugin의 코드와 PNG·토큰으로 가능한 구현을 계속하되,
로컬 시안과 실제 Figma 생성·내보내기 결과를 구분해 보고해.
Claude 링크 재접속이나 Figma 접근을 전체 작업의 선행 조건으로 삼지 마.

분석에서 끝내지 말고 구현 → 빌드·자동 테스트 → 접근 가능한 승인 실기기 검증까지 진행해.
밝은/어두운 테마, 큰 글꼴, 연결 복구, 장비 전환과 늦은 응답,
중복 명령 방지와 선택·초안 보존을 확인해.
운영 장비의 전원·네트워크·파일은 임의로 변경하지 말고,
실행하지 못한 검증을 통과했다고 보고하지 마.

최종 스타일 규칙, 변경 전후 실제 앱 캡처와 검증 결과를 별도로 남겨.
문서의 전체 완료 조건을 충족하면 마지막 단계에서
처음 기록한 JETSONCONTROLLER_COBALT_FIELD_V5.md 한 파일만 삭제해.
필수 구현이나 검증이 남아 있으면 이 MD를 유지하고 차단 사유를 명확히 보고해.
