# Cobalt Field — 영구 스타일 가이드

Jetson Controller용 최종 색상 인계 기준 · V5 / 2026-09-08

이 파일은 일회성 작업 지시서가 아니며 완료 후 삭제 대상이 아닙니다. 시안 수치는 데모이고 실제 앱 데이터가 아닙니다. 최신 사용자 요청에 따라 V4의 포리스트·라임색을 네이비·코발트·오프화이트로 대체합니다.

**이 세트의 구현 시각 기준은 마지막 Cobalt Field 보드입니다. 중간에 생성된 홍보용 이미지 두 장은 색상·화면·기능 계약으로 사용하지 않습니다.**

## 1. 원본 캡처에서 유지한 것과 새로 설계한 것

### 1.1 원본에서 확인한 것

S01~S08은 `reference/01_user_reference.png`~`08_user_reference.png`에 대응한다. 원본명과 SHA-256은 `reference/manifest.json`에 있다.

| 근거 | 관찰 |
|---|---|
| S01 / S02 | 장비 헤더, 현재 작업, 준비 상태, 전송 대기 요약, 홈 선택 |
| S03 | 실행 중·시작 요청 중·실패 작업 카드, 추가·상태·중지 동작 |
| S04 / S05 | 전송 대기/장비 파일, 대상·용량 확인, 선택, 이력, 하단 전송 버튼 |
| S06 / S07 | 장비 설정·앱 설정·위험 동작, 테마와 상태 보존 토글 |
| S08 | 장비명과 중단 영향을 안내하는 재부팅 확인창 |

8장은 밝은 테마, 기본 글꼴, 정상 연결, 등록된 장비를 선택한 정지 화면이다. 어두운 테마, 큰 글꼴 배치, 끊김 상태, 등록 전 화면, 상세 동작은 직접 관찰한 원본이 아니라 **이번에 보완한 설계**다.

왼쪽 테스트 패널, 검은 휴대전화 프레임, 가짜 시계·배터리, 웹 스크롤바는 제품 화면에 넣지 않는다. 시안의 “조건에 따라 문구가 바뀌지 않는다”는 설명은 제품 요구가 아니다. 제품에서는 실제 상태에 따라 문구·가용 행동이 바뀌어야 한다.

### 1.2 핵심 판단

**홈·작업·데이터·설정의 구조는 유지하고 시각 언어와 동작 흐름은 리빌딩한다.** 사용자는 새로운 메뉴를 다시 학습하기보다, 지금 실행 중인 작업과 문제가 무엇인지 더 빨리 읽을 수 있어야 한다.

| 항목 | V5 결정 | 이유 |
|---|---|---|
| 현재 작업 | 짙은 네이비 표면의 핵심 카드 | 다른 관리 항목보다 먼저 읽히게 함 |
| 화면 배경 | 약간 따뜻한 중립색 | 검은 글자·짙은 작업 카드와 명확한 위계 |
| 강조색 | 코발트·아이스 블루 포인트 | 주요 행동·선택에만 집중; 성공 의미와 분리 |
| 준비 상태 | 요약 타일 + 필요한 상세 | 정상 항목의 긴 반복 행을 줄임 |
| 카메라/GNSS | 홈의 명확한 바로가기 | 센서 탭을 없애도 자주 쓰는 기능이 멀어지지 않게 함 |
| 하단 내비게이션 | 불투명한 고정 영역 + 선택 capsule | 원본의 선택 강조는 유지, 떠 있는 바의 여분 공간·중첩을 줄임 |
| 데이터 선택 | 실제 전송 단위 중심 | 폴더 API에 파일 체크 UI를 억지로 붙이지 않음 |
| 상태 보존 토글 | 제거; 자동 보존 | 복원은 사용자가 켜야 하는 옵션이 아님 |
| 팬·전원·진단 | 설정 안으로 이동 | 능력은 유지하면서 홈의 기술적 잡음을 줄임 |
| 위험 확인 | 대상·영향·구체적 확정 행동 | 실수 방지, 모호한 “확인” 버튼 제거 |

`153 GB`, `42분`, `128개`, `RTK FIX`, 서버 이름, 경로와 시각은 모두 **시안용 데이터**다. 없는 API 필드를 제품 코드에 만들어 넣거나 release에서 기본 정상값으로 사용하지 않는다.

## 2. 2026 시점의 디자인 방향: 무엇을 채택할 것인가

여기서 말하는 “2026 방향”은 모든 제품이 따라야 하는 유행 목록이나 시장점유율 주장이 아니다. **현재 공개된 Google·Apple·Android 공식 지침에서 이 현장용 Android 앱에 도움이 되는 부분을 선택한 설계 판단**이다. 2025년에 소개된 방향도 2026 시점에 참고한 것으로 표시한다.

### 2.1 목적 있는 표현력

Google의 Material 3 Expressive 설명은 표현력, 사용성, 접근성과 상황 적합성을 함께 다루며, 표현적인 디자인이 반드시 요란해야 하는 것은 아니라고 설명한다. [D1]

**적용:** 현재 작업에만 강한 명암, 의미 있는 크기 차이, 주요 행동의 색 대비를 준다. 모든 카드를 같은 강조색으로 만들거나 모든 상태를 움직이게 만들지 않는다. 네이비/코발트 조합 자체가 공식 M3 팔레트라는 뜻은 아니다. 이는 이번 제품을 위한 신규 제안이다.

### 2.2 콘텐츠와 제어 영역의 분리

Apple의 Liquid Glass 설명은 콘텐츠와 내비게이션/제어 레이어의 역할을 구분하며 유리 효과의 무분별한 중첩을 피하도록 안내한다. 이 자료는 Apple 플랫폼의 방향이다. [D2]

**적용:** 하단 탐색과 상황별 주요 행동을 하나의 측정 가능한 영역으로 분리한다. **Android 현장 도구에는 유리 굴절·배경 블러를 이식하지 않는다.** 이 원칙은 시각적 구분을 위한 참고이지 iOS 컴포넌트 복제 지시가 아니다.

### 2.3 접근성을 예외가 아닌 기본 구성으로

Compose 기본 컴포넌트는 역할별 semantics와 터치 영역을 제공하며, 공식 안내는 상호작용 대상의 최소 크기 48dp를 설명한다. [D3] Android는 200%까지의 비선형 글꼴 확대를 지원하므로 실제 OS 설정에서 검증해야 한다. [D4]

**적용:** 주요 버튼은 최소 52dp, 주요 행은 48dp 이상, 본문은 16sp를 시작값으로 사용한다. 고정 높이에 글자를 끼워 맞추지 않는다. 로컬 HTML의 2.0배는 **선형 스트레스 시안**일 뿐 Android의 비선형 확대를 재현한 것이 아니다.

### 2.4 이 제품에 추가로 적용하는 판단

“연결됨”보다 **현재 어떤 동작이 가능한지**, “실행 중”보다 **언제 확인한 상태인지**가 중요하다. 따라서 최신성, 확인 불가, pending 명령, 미지원 이유를 주요 UI 정보로 다룬다. 이는 이번 앱의 성격에서 도출한 제품 판단이며 통계적으로 검증된 유행이라고 주장하지 않는다.

AI 챗봇, 자동 행동 추천, 3D 장비 모델, 화려한 지도·차트를 트렌드라는 이유로 넣지 않는다. 현재 앱에서는 잘못된 상태나 중복 명령을 줄이는 것이 우선이다.

## 3. Cobalt Field 스타일 가이드

### 3.1 디자인 원칙

**명확한 위계 / 상태의 정직함 / 적은 장식 / 일관된 행동 / 장비 문맥 유지**를 공통 기준으로 삼는다.

루트 화면 하나에는 가장 중요한 카드와 행동이 분명해야 한다. 정상 데이터를 장식 그래프로 바꾸지 않는다. 카드 크기는 정보량으로 정하며, 큰 여백으로 클릭 수가 늘어나면 조정한다. 실패나 끊김을 숨기지 않되 화면 전체를 빨갛게 만들지 않는다.

### 3.2 색상 토큰

`design/tokens.json`이 정확한 값의 기준이다. 다음은 **마지막 Cobalt 시안에 맞춘 V5 역할 기반 팔레트**다. Light의 핵심 표면·문자·주요 버튼 역할은 직전 PNG의 평탄한 픽셀 영역을 대조했다. 세부 상태색 쌍과 Dark는 누락된 역할을 완성한 제안값이다. 보이지 않은 원본 화면에서 추출했다고 주장하지 않는다.

브랜드 포인트와 상태 의미를 분리한다. 코발트는 주요 행동, 아이스 블루는 선택/짙은 표면 위 행동, 인디고는 확인된 성공·완료 역할이다. 파란색이라는 이유만으로 “성공 완료”를 판정하지 않는다. 초록·청록·포리스트·라임을 브랜드와 상태 배지에 다시 넣지 않는다. 배지에는 반드시 `실행 중`, `시작 요청 중`, `실패`, `현재 상태 미확인`처럼 문구를 넣는다.

본문과 보조 설명의 사용 쌍은 대비 4.5:1 이상을 프로젝트 목표로 한다. 의미를 전달하는 경계/아이콘은 3:1 이상을 별도 검사한다. 장식용 연한 카드 테두리만으로 선택 상태를 전달하지 않는다. 제공된 대비 검사는 24개 대표 텍스트 쌍의 계산이며 앱 전체 접근성 인증이 아니다.

MaterialTheme의 `surfaceContainer*`, `onSurfaceVariant`, container/on-container 쌍, error 계열까지 명시해 기본 보라색·청록색 등 의도하지 않은 팔레트가 일부 화면에 섞이지 않게 한다. 인디고 상태색은 명시된 토큰만 사용한다. 색을 화면별로 하드코딩하지 않는다. 시스템 따름·밝게·어둡게를 제공하고 기존 설정을 유지한다.

### 3.3 타이포그래피

| 역할 | 시작 크기 / 굵기 | 사용 |
|---|---|---|
| 화면 제목 | 26sp / 700 | 작업, 데이터, 설정 |
| 핵심 카드 제목 | 24sp / 700 | 현재 작업 |
| 작업/그룹 제목 | 20sp / 700 | 목록 카드, 요약 |
| 중요한 수치 | 23~28sp / 700 | 실제 값이 있을 때만 |
| 일반 본문/행 제목 | 16sp / 400~500 | 주요 정보 |
| 보조 설명 | 14sp / 400 | 원인, 다음 행동 |
| 버튼 | 15~16sp / 700 | 실행/조회 |
| 부가 메타/배지/탭 | 12~13sp / 500~700 | 단위, 보조 시각, 상태 |

Figma용 폰트는 Noto Sans KR을 우선한다. 로컬 PNG는 환경의 Noto Sans CJK KR로 렌더링했다. Android에서는 기존 `FontFamily.SansSerif` 또는 검증된 프로젝트 폰트를 우선하며 시안과 픽셀 일치를 위해 새 대용량 폰트를 강제로 번들하지 않는다. **폰트 바이너리는 패키지에 포함하지 않는다.**

한글 본문 줄높이는 약 1.5, 큰 제목은 약 1.32를 출발값으로 한다. 실제 한글 잘림·기기 폴백을 확인한다. 오류 이유를 12sp의 한 줄로 줄여 숨기지 않는다. 숫자 소수점, 파일 확장자, device ID의 판별 가능한 부분을 보존한다.

### 3.4 간격·형태·아이콘

화면 좌우 여백은 20dp를 기본으로 하고 360dp 이하에서는 16dp까지 조정할 수 있다. 카드 내부는 16~20dp, 큰 설명 카드/모달은 24dp를 사용한다. 간격의 기본 단위는 4dp이며 8/12/16/20/24/32dp를 중심으로 정리한다. 로컬 시안에 사용된 작은 보정 간격을 모든 화면에 새 토큰으로 증식시키지 않는다.

배지 8dp, 작은 제어 12~14dp, 일반 그룹 18~20dp, 핵심 카드 24dp, 모달 26~28dp 안팎을 출발값으로 쓴다. 원형은 작은 아이콘 버튼과 선택 표시처럼 의도가 있을 때만 사용한다.

아이콘은 하나의 선형 계열을 사용한다. 제공 SVG는 24 좌표계의 자체 제작 참고 아이콘이며 PNG가 아니다. 실제 앱에서는 기존 Material 아이콘으로 같은 의미를 유지해도 된다. 아이콘만 있는 버튼은 48×48dp와 접근성 이름을 제공한다.

### 3.5 모션·성능

전환의 출발값은 단순 상태 강조 120~180ms, 상세/확인창 180~240ms다. 이는 제품 제안값이며 실측 결과가 아니다. 이동·확대·흔들림이 핵심 정보를 방해하면 생략한다. OS 모션 설정을 존중하고, 변화가 없는 숫자·아이콘을 계속 애니메이션하지 않는다.

배경 블러, 굴절, 무한 shimmer, 3D, 홈 자동 영상, 새 지도 SDK, 대형 차트 라이브러리를 추가하지 않는다. 새 디자인이 별도의 폴링 루프나 상시 카메라 연결을 만들면 실패다. 예시 PNG·원본 캡처·HTML은 release APK에 넣지 않는다.

### 3.6 공통 구성요소 계약

`DeviceContextHeader`, `ConnectionNotice`, `CurrentTaskCard`, `ReadinessTile`, `TaskStateCard`, `FolderSelectionRow`, `TransferActionArea`, `GroupedSettings`, `ConfirmDeviceAction`, `EmptyState`, `CobaltNavigation`을 화면 간 공유한다. 이미 같은 책임의 구성요소가 있으면 중복 작성하지 않고 정리한다.

이번 로컬 Figma 생성기는 **Button/Badge variants, 아이콘 인스턴스, 텍스트 스타일과 색상·간격 변수**를 생성하도록 작성했다. 모든 고수준 카드가 이미 완전한 재사용 컴포넌트로 출판됐다고 가정하지 않는다. 구현 단계에서는 카드와 shell까지 프로젝트 규칙에 맞게 공통화한다.

### 4.1 내비게이션

```text
홈        : 선택 장비 / 현재 작업 / 준비 상태 / 결과 요약
작업      : 목록 / 추가 / 시작 전 확인 / 상세 / 설정·로그·결과
데이터    : 전송 대기 / 장비 파일 / 대상·선택 확인 / 진행·검증·이력
설정      : 네트워크·센서·팬·서버·진단 / 앱 설정 / 위험 동작
공통      : 장비 선택·등록 / 알림 목록 / 연결 복구
```

센서와 알림을 별도 하단 탭에서 제외하는 것은 **접근 경로 통합**이다. 카메라·GNSS·RTK·IMU·알림 이력·임계값 설정 기능을 삭제하지 않는다. 모든 장비 관련 화면에서 선택 장비를 식별할 수 있어야 한다. 루트 헤더의 알림 진입점은 공통으로 유지한다.

하단 탭을 다시 누를 때 중복 route를 쌓지 않는다. 상세에서 돌아오면 이전 탭·스크롤·필터로 복귀한다. 전송 CTA와 내비게이션은 공통 하단 영역에서 함께 측정해 본문이 둘의 전체 높이를 피하도록 한다. IME와 Android 시스템 인셋을 두 번 더하지 않는다.

### 4.2 홈

**현재 작업 → 준비 상태 → 결과** 순서를 유지한다. 짙은 카드에는 작업명, 실제 실행/명령 상태, 출처가 있는 경과 시간과 저장 결과만 표시한다. 상태 보기와 중지는 분리한다. 중지는 접근 가능하게 두되 실수로 누르기 쉬운 주 행동과 동일하게 강조하지 않는다.

필수 조건을 모두 확인하지 못했는데 “수집 준비 완료”라고 쓰지 않는다. 저장률만 있으면 남은 GB를 계산해 만들어 넣지 않는다. 여러 작업이 실행 중이면 대표 1개와 `실행 중 N개`로 목록에 연결한다.

연결이 끊긴 뒤에는 `작업 없음`으로 바꾸지 않는다. 마지막 실행 상태와 확인 시각을 보관하고 `현재 상태 미확인`으로 구분한다. 실제 카메라 프레임 없이 홈 썸네일에 LIVE를 붙이지 않는다.

### 4.3 작업 목록·상세·추가

작업 카드의 기본 정보는 작업명, 실행 상태, 최근 결과, 다음 행동이다. Python 경로·부팅 시 실행·등록 해제·로그 전문은 상세/메뉴로 이동한다. 기능 자체를 제거하지 않는다.

| 상태 | 표시와 행동 |
|---|---|
| 대기 | 실제 조건이 맞으면 시작; 시작 전 확인으로 연결 |
| 시작 요청 중 | 요청 접수/전송 중 표시; 이중 요청 차단 |
| 실행 확인 | 실행 중; 상태·결과·중지 접근 |
| 실패 | 짧은 원인과 문제 확인; 조건을 충족할 때만 재시도 |
| 중지 요청 중 | 요청과 실제 종료를 분리; 완료를 앞당겨 표시하지 않음 |
| 응답 확인 불가 | 이전 상태+확인 필요; 재명령보다 조회 우선 |
| 미지원/권한 부족 | 원인과 해결 경로; 가짜 활성 버튼 금지 |

신규 **시작 전 확인**은 기존 capability·작업 요구사항을 재사용한다. 작업을 시작해야 활성화되는 카메라 때문에 영원히 시작할 수 없는 순환 조건을 만들지 않는다. 필수 조건은 차단, 선택 조건은 안내로 분리한다. 단순한 일상 실행마다 불필요한 다중 모달을 추가하지 않는다.

상세는 상태·결과·로그·설정의 역할을 구분한다. UI를 열거나 회전했다는 이유로 작업을 시작하거나 부팅 설정을 다시 저장하지 않는다. 로그는 필요할 때 읽고 계속 전체 목록에 방송하지 않는다.

### 4.4 데이터·전송

원본의 “파일 3개 선택” 모양을 그대로 강제하지 않는다. 조사한 기존 업로드 흐름의 입력은 `rootId`, `path`, `targetId` 기반이다. 임의 파일 묶음 API가 이미 있다고 단정할 수 없다. [R1]

실행 에이전트는 현재 `JetsonRepository.startUpload`와 백엔드 검증을 끝까지 읽어 지원 단위를 확정한다. 폴더 단위면 V5처럼 `폴더 선택/폴더 N개 전송`으로 구현한다. 단일 폴더 job만 지원하면 여러 폴더 선택을 하나의 job이라고 꾸미지 않는다. 검증된 순차 배치와 개별 job 대응을 만들거나 우선 한 폴더씩 전송하게 조정한다.

파일 단위가 실제 지원될 때만 파일 체크 UI를 제공한다. **3개 선택 후 부모 폴더 전체를 전송하는 행동은 금지**한다. 루트·정규화 경로·권한·출처 요약 검사를 그대로 유지한다.

새 항목은 기본 미선택이다. 시안의 1개 체크는 사용자가 선택한 후의 예시다. 선택을 해제하는 것은 원본 삭제가 아니다. 검색/필터로 가려진 선택은 개수와 범위로 드러내고 장비 A의 선택을 B에 넘기지 않는다.

전송 준비는 제어 연결, 전송 경로, 서버 설정, 서버 인증/접근, 원본 선택, 용량 확인을 분리한다. 과거 확인한 `TransportPolicy.kt`는 LAN에서만 서버 업로드 시작을 허용한다. UI 때문에 이 정책을 해제하지 않는다. 모바일 RTK 중계는 이 파일 전송 기능과 별개다. 현재 브랜치에서 정책이 달라졌다면 코드·테스트·실제 경로를 함께 확인한다. [R2]

LAN 연결만으로 `서버 응답 확인됨`을 표시하지 않는다. 사전 확인 API가 없으면 `대상 서버 접근은 전송 시 확인`처럼 사실대로 쓴다. 크기 미확인을 0 B로 표시하지 않고 기존 필수 검사를 우회하지 않는다.

전송 직전에 **대상 장비 → 대상 서버 → 선택 단위/개수/알려진 용량**을 확인한다. 대기·전송·검증·완료·실패를 분리하고 실제 바이트/서버 값이 없으면 가짜 진행률·남은 시간을 만들지 않는다. 실패한 job/원본만 안전하게 재시도하며 완료 항목 전체를 재전송하지 않는다. 일시정지/재개는 실제 API가 있을 때만 노출한다.

### 4.5 설정·위험 동작

설정은 실제 허브로 만든다. 기존 알림 설정 화면의 제목만 `설정`으로 바꾸지 않는다. 네트워크, 센서, 팬, 서버 대상, 장비 진단과 앱 알림·테마에 연결한다.

`장비 전환 시 화면 상태 유지` 토글은 제거한다. 장비별 스크롤·검색·선택·초안 보존은 기본 동작이다. 저장된 정상 상태를 현재 live 상태로 복원하는 기능은 아니다.

팬 지원 여부, 자동 모드, 최소 수동 속도는 실제 장비가 결정한다. 팬이 없는 장비는 해당 항목을 숨기거나 명확하게 미지원으로 표시한다. Wi-Fi Direct 전환의 공유기·휴대전화 인터넷·서버 전송 영향은 현재 정책에 맞게 알린다.

재부팅·전원 종료·등록 삭제는 각기 다른 기능이다. 확인창에 대상 장비와 실제 중단 영향을 넣고 구체적인 확정 버튼을 사용한다. 취소·뒤로 가기·바깥 닫기는 명령 0회다. 모달 중 장비가 바뀌면 닫거나 재확인한다. `1~2분` 등 재부팅 시간을 측정하지 않았다면 표시하지 않는다.

등록 삭제가 측정 파일 삭제나 장비 초기화라는 뜻이 되면 안 된다. 코드상 부수 효과를 확인해 안내한다. 경고를 닫았다는 사실을 문제 해결로 바꾸지 않는다.

### 4.6 센서·영상·GNSS

구성 여부, 장치 연결, 수신, 데이터 최신성은 별도 사실이다. 홈과 상세가 같은 상태 원천을 사용하도록 한다. 카메라 바로가기는 실제 프레임 스트림을 필요할 때 열며, 화면 이탈 시 미리보기 자원을 정리한다. 앱 미리보기를 닫았다고 Jetson의 수집 작업을 중지하지 않는다.

LIVE/지연/마지막 수신 화면을 구분한다. GNSS에서는 장비 위치와 휴대전화 위치, NTRIP 연결·RTCM 수신과 RTK FIX, 지도 로딩과 텔레메트리 수신을 분리한다. 실제 정확도·보정 나이가 없으면 값을 발명하지 않는다.

### 4.7 최초 등록·장비 전환·복구

미등록 화면에는 가짜 JETSON-01 연결됨 상태를 표시하지 않는다. QR, 수동 등록 코드, 권한 거절 대안을 유지한다. 등록과 인증, 연결과 제어 가능 여부를 구분한다.

장비 선택기는 현재 선택·발견됨·등록만 됨·미연결을 구분한다. A→B→A 전환은 A의 초안을 돌려주되 A의 늦은 응답이 B 화면에 들어오면 안 된다. 전환 자체가 작업 시작/중지 명령이 되어서는 안 된다.

끊김은 한 곳에 지속 배너로 보여주고 현재 화면과 입력을 유지한다. 연결 허브로 강제로 쫓아내지 않는다. 즉시 모달·Snackbar·카드 경고를 모두 중복 띄우지 않는다. 복구 화면은 경로별로 다음 행동을 안내하며 기존 재연결 엔진을 재사용한다.
